# ADR-0009: Artifact class decides the mechanism

- **Status:** Accepted · **Date:** 2026-08-20 · **Deciders:** Enterprise Architect, Tech Lead, Patterns Expert, SRE, Data & Persistence Architect
- **Context spec/architecture:** `docs/specs/agent-coordination.md` (M1, US-5), `docs/architecture-agent-coordination.md` §4.4

## Context

The measurement that reframed the whole capability: **the six busiest files in TheTerrace are all generated** — 58/60, 58/60, 58/60, 54/60, 35/60 and 33/60 of the last sixty commits on `main` — against **13/60** for the busiest hand-written source file. With 26 worktrees in play, any two concurrent branches conflict on derived content *by construction*. Nobody's authored work disagrees; **the generator ran twice**.

A uniform lease is the wrong instrument for that. It would have prevented none of those conflicts — both agents are entitled to regenerate — while serialising work that is not in contention at all.

The cost is not the conflict itself, which resolves in seconds. It is the loop it sustains: a conflicted PR keeps the branch conflicted, **a conflicting PR runs no `pull_request` workflow at all** (`CI-A`), the branch falls further behind, and it conflicts again.

## Decision

We will maintain a committed, PR-reviewed **artifact-class registry** assigning every path pattern exactly one class, and **the class will decide the mechanism entirely**:

| Class | Mechanism |
|---|---|
| `authored` | Hard lease; an unleased write is refused |
| `derived` | **Never leased.** `.gitattributes merge=<driver>` regenerates on conflict |
| `register` | Allocator (ADR-0008) plus an entry-count conservation assertion at merge |
| `hotspot` | Claimable only by the `integrator` role; others record a request |

An unclassified path defaults to `authored` — the safe direction.

## Alternatives considered

- **A uniform lease over every artifact (the draft).** Rejected on the measurement above. It aims the mechanism at 13/60 and misses 58/60.
- **A post-hoc regeneration script run after a rebase** (TheTerrace's `sync-generated.ps1`). Partially superseded rather than dismissed: it is real, it works, and it reduced a multi-step resolution to one command. But it acts *after* the conflict exists and only when someone remembers to run it — and the same script is the recorded instance of both `CTRL-E` (a control that assumed its own steps worked and lost work twice while reporting success) and `CTRL-G` (a wildcard stage that swept another session's files into its commit). A merge driver acts earlier and cannot be forgotten. **Its hardening is carried forward as requirements**, not re-derived: read every exit code, verify the push against the remote ref, compare commit subjects across the rebase, and stage by explicit name.
- **Stop committing derived artifacts.** The genuinely structural fix, and rejected for this layer: several of them are the browsable surfaces the repository publishes from `docs/`, so not committing them means not shipping them. Left as a separate decision that this ADR does not foreclose.
- **Regenerate on a post-merge job on `main` instead.** Rejected for v1: it changes how every session synchronises, and it leaves the PR conflicted in the meantime, which is the state that costs the gate.

## Consequences

- **+** **Spiked, not assumed.** *Spike S6:* with a `merge=regenerate` driver registered and two branches each changing a derived **and** an authored file, the derived file resolved clean and was **absent from the unmerged list**, while the authored file **still conflicted normally**. Scoping by `.gitattributes` is exact — the driver cannot reach an authored file.
- **+** The vicious loop is broken at the conflict rather than at the gate.
- **+** The class registry is a small, human-legible dimension that a reviewer can argue with in a PR.
- **−** **The driver's registration lives in `.git/config`, which is per-clone and per-worktree and is never committed.** A fresh clone or a new worktree silently gets default behaviour. This is exactly the recorded `CTRL-E` instance — a `git config` that failed with nothing checking, leaving the driver unregistered while the setup script reported success. The layer therefore **reads the configured value back** and reports an unregistered driver as a finding rather than assuming it.
- **−** A misclassified artifact is a real hazard: marking an authored file `derived` would let a merge overwrite someone's work. Mitigated by defaulting to `authored`, by requiring the registry to be reviewed in a PR, and by the driver failing closed on any conflict outside the declared set.
- **−** Registry drift: a new generated file that nobody classifies conflicts the old way. Detectable by comparing generator outputs against the registry, and worth a control later.
