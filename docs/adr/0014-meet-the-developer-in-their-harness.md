# ADR-0014: Meet the developer in their harness

**Date:** 2026-10-19 · **Decided by:** the owner · **Status:** accepted

## Decision

The AI-Forward Pack **must meet the developer where they are.** Every harness a developer codes in is a
first-class target of the pack. The pack's skills, knowledge, personas, scripts and hooks work there
properly, out of the box. Supporting the harnesses is not a feature of the pack, and not a cost to
weigh against other work: it is what the pack is for.

Supported today: **Claude Code** (`.claude/`), **GitHub Copilot** (`.github/`), **Codex**
(`.agents/skills/`, `.codex/`), **Grok Build** (`.grok/`), **Antigravity** (`.agents/`) and **Muse**
(`.agents/skills/`, `muse-surface.md`). **Local LLMs** are in scope and **not yet supported** (see Gaps).

## Why

The owner uses all of these harnesses, and local LLMs as well. In the owner's words: *"if the pack
does not support them properly out of the box then coding in a repo with the pack applied in a
harness becomes sub optimal … unless you explicitly support the different harnesses different issues
pop in terms of the skills, knowledge, scripts etc."*

The defect register shows that pattern repeatedly. Each item below was a harness that was nominally
covered and still failed:

- **HOST-A:** a host loaded our config, logged success, and silently ignored the entries whose shape
  was not its own. Antigravity's `PostToolUse` handler loaded and never fired.
- **PACK-U:** a host's scan of another host's directories was treated as an install. Turning the
  compatibility setting off, or looking up the host's own documented paths, found nothing.
- **CTX-B:** Copilot CLI loads both `AGENTS.md` and `CLAUDE.md`, so instructions written for one
  harness were paid twice in another.
- **PACK-C:** an interpreter, shell or path form correct on the author's platform was wrong on
  another. That is the same class of failure, across platforms instead of hosts.

"Works with" is not support. Each harness has its own discovery paths, config schemas, hook
contracts, loading rules and tool names, and a difference left unhandled becomes a defect in that
harness.

## What this obliges

1. **A native surface per harness.** Each supported harness has a destination in its own documented
   layout in the deployment map, generated by `tools/sync-pack.ps1`, with a path map that tells the
   agent where things are (for example `.grok/rules/grok-surface.md`, `.agents/rules/agy-surface.md`,
   `muse-surface.md`). Another host's compatibility scan never counts as support (PACK-U).
2. **The host's own shapes.** Hooks, configs and instructions are written in each host's schema, and
   a contract that has not been observed on that host is marked unverified, never assumed (HOST-A).
   For example, the git-identity guard stays unwired for Antigravity until its deny contract is seen.
3. **Verified on the host.** A harness is called supported only after the pack has been observed
   working on it: skills found, knowledge read, hooks firing, scripts running.
4. **Parity is the floor.** No change drops or degrades a supported harness to save effort, bytes or
   gates. Trimming `AGENTS.md`, simplifying sync, or cutting a "rarely used" surface must keep every
   harness's grounding intact. A change to `pack/` is done only when it reaches every surface (the
   sync and drift gates).
5. **Adding a harness** follows from developers using it. It needs a native adapter, a path map, hooks
   where the host has them, and tests, and it is listed as supported only once item 3 holds.
6. **Removing a harness** happens only when developers no longer use it — never for cost.

## Rejected

- **One canonical harness, with the others through compatibility layers.** Rejected: that is the
  PACK-U and HOST-A failure as a policy.
- **Dropping low-use harnesses to cut `AGENTS.md` bytes or gate time.** Rejected: the cost of
  support is the price of the pack's purpose, not a reason to trim it. Make each surface cheaper
  instead (CTX-B), not fewer.
- **"Best effort" support with no host verification.** Rejected: a surface that loads but does not
  fire is worse than none, because it looks covered.

## Gaps against this decision (2026-10-19)

- **Local LLMs: no support.** No adapter, path map, test or mention exists for any local-model setup.
  Tracked as FR-108.
- **Native hosts refuse writes outside the repository** (FR-100). That is a harness behaving worse than
  Claude for the same pack.
- **Antigravity runs without the git-identity guard** (deny contract unobserved). This is recorded
  under PK-07.
