Architecture · draft · tier T2

Agent coordination

A git-tracked append-only record of intent, folded on demand with no daemon and no database; enforced at each harness's edit boundary and at the universal commit boundary; with a non-coordinating allocator and a merge driver that regenerates derived artifacts rather than merging them. Six spikes were executed. Four of them overturned the obvious answer.

S1 + S1b · the allocator

The stdlib answer was the wrong answer

uuid.uuid7() is the obvious choice. On the installed interpreter — 3.12.10 — it raises AttributeError; it landed in 3.14. This repository's CI pins python-version: "3.x", meaning whatever is newest. A stdlib call that exists on the runner and not on the developer's machine is the PACK-J class by construction, and adopting it would have been a defect authored inside the architecture that names the class.

So: 48 bits of millisecond timestamp, 80 bits from os.urandom, Crockford base32, 26 chars, about ten lines. Then tested against the exact condition that defeated the 22-branch scanner — 8 separate processes, 500 ids each, all pinned to the same millisecond, no shared state, no network.

issued=4000   unique=4000   collisions=0  →  COLLISION-FREE WITHOUT COORDINATION
S2 · the substrate

The daemon and the database are both cut

The draft assumed replaying a log per edit would be too slow, and never measured it. Measured here as a hook actually invokes it — a subprocess, folding a 10,000-event, 1.45 MB, 12-file record, then matching a glob:

bare python -c pass    median 14 ms   p95 15 ms  (the floor nothing can remove)
full fold, 10k events     median 45 ms   p95 47 ms
amortised snapshot       median 22 ms   p95 27 ms

The naive fold meets the 100 ms budget with roughly 2× headroom — which also sets the compaction trigger rather than leaving it to taste: compact above 10,000 live events, or when measured p95 exceeds 60 ms.

S3 · the record

Concurrent appends do not corrupt — so the reason for one-file-per-session changes

6 processes × 200 records × ~4 kB through one O_APPEND descriptor on Windows.

1200 lines   expected 1200   unparseable=0  →  ATOMIC

A shared file is safe. One-file-per-session is kept for reviewability, not for safety — and recording the real reason matters, because a maintainer told "concurrent appends corrupt the file" would have been told something false. The genuine hazard is the LOG-A seam: an append onto a file that does not end in a newline fuses two records and loses both.

S4 · work preservation

Why the guard reported SAFE for the case it existed to catch

Reproduced in a scratch repo on a branch genuinely holding one commit reachable from no other ref:

git rev-list HEAD --not --all  →  0   (reports SAFE — the recorded bug)
--exclude=<branch> --all    →  0   (fails identically)
explicit peers, no --all   →  1   (correct)

The mechanism, now established rather than guessed: --all implicitly includes HEAD, so the expression reduces to HEAD --not HEAD. Excluding the branch does not exclude HEAD, which is why the second form fails too. --all is forbidden in this expression.

S5 · enforcement

A hook can refuse an edit — and three details the schema gave up

Contract read from the authoritative settings schema, then the hook program executed against the real payload shape across five cases. All five correct, including both fail-safe paths:

held by another  →  deny + holder · expiry · reason · remedy
free artifact      →  allow
my own lease       →  allow
identity unset     →  ask — "NOT CHECKED"
malformed payload  →  ask — "NOT CHECKED", no crash
  • args exec-form spawns the command directly with no shell, substituting path placeholders per element as plain strings — "so paths with quotes, $, or backticks never reach a shell parser." That closes Meridian's SHELL-A class structurally rather than by care. It is not the default.
  • The if pre-filter decides whether the process is spawned at all. With 14 ms of every call being interpreter startup, this is the largest latency lever available and costs nothing.
  • additionalContext — "text injected into model context" — is the exact channel that makes §STRIDE's elevation row a live path rather than a theoretical one.
S6 · derived artifacts

A merge driver resolves derived conflicts and cannot reach authored files

Two branches, each changing a derived and an authored file, with a .gitattributes merge=regenerate driver registered:

derived.txt  →  resolved clean, absent from the unmerged list
src.txt      →  still conflicted, normally

M1 is solvable at merge time, not only by a post-hoc script, and the scoping is exact.

A seventh result, found by accident and kept. The first run of the S1b verdict printed "COLLISION-FREE WITHOUT COORDINATION" over zero ids, because the workers had crashed and the check only compared len(set(x)) == len(x). That is the "a control that scanned nothing, reported clean" class — produced live, while building a control. It is now an architectural rule: every control asserts its corpus was the size it assumed before it is allowed to report a pass.

The system as a system

Stocks, flows, loops, delays — and where the leverage actually is

The loop to break

A derived-file conflict keeps a PR conflicted → a conflicting PR runs no gate at all → the branch falls further behind → it conflicts again.

That loop is broken at the conflict (ADR-0009), not at the gate.

The two delays that decide the design

The gate delay (~4 min) exceeds the merge interval on a busy afternoon (~10 min and shrinking), so the window between green and merged is routinely lost.

The push delay — between minting an id and pushing it — is exactly the window a branch scanner cannot see into. The allocator is designed for the second; the lease for the first.

The leverage point is not the lease. Meadows ranks rules of the system above information flows, and above both sits the power to change structure. A lease adds an information flow. Making a collision unrepresentable, and making a derived conflict resolve itself, changes the structure — which is why ADR-0008 and ADR-0009 outrank ADR-0010 here, even though the lease is the visible feature.

Two shapes, and why this one

The decisive argument is failure mode, not performance

Shape A — coordination service rejected

A local daemon owning SQLite; agents talk over MCP/stdio. Atomic leases, real queries, one surface.

Rejected on measured evidence. S2 shows the file fold meets the budget with headroom, so the daemon buys nothing this system needs — and costs a startup story, a liveness problem, crash recovery, and a failure mode that violates the "no daemon before an agent can work" requirement.

Shape B — record + fold chosen

Append-only record of intent, git-tracked, one file per session; all state a fold; enforcement in the harnesses that already have edit boundaries; derived-file conflict pushed down into git itself.

Shape A's failure is the service is down and nobody can work — an availability dependency introduced into an offline local tool. Shape B's failure is the record is unreadable, so the layer says NOT CHECKED and degrades to advisory. For a control whose recorded ancestors failed by reporting success, a loud non-blocking failure is worth more than the 20 ms.

Components, boundaries, and the class that decides everything

coord core is a pure library; every surface is a thin host over it

Artifact class → mechanism

An unclassified path defaults to authored — the safe direction.

Three boundaries, as trust levels

  1. Agent → record. Semi-trusted. A session controls its own file and nothing else; content is length-capped and scrubbed on the way in.
  2. Record → projection → another agent. Untrusted. The one genuinely new boundary — see STRIDE below.
  3. Layer → git. Trusted but unverified — every git invocation reads its result back, because an exit code is not a result.

The registration hazard. The merge driver lives in .git/config, which is per-clone and per-worktree and never committed — so a fresh worktree silently gets default behaviour. That is exactly the recorded instance where a git config failed with nothing checking, leaving the driver unregistered while the setup script reported success. The layer reads the value back and reports an unregistered driver as a finding rather than assuming it.

The six decisions

Each with its strongest rejected alternative — a decision with no rejected alternative was not a decision

ADR-0007

A git-tracked append-only record, folded on demand — no daemon, no database

All state is a fold over an append-only JSONL record, one file per session. A snapshot may exist as a labelled, rebuildable cache, never a source. Grain: one row is exactly one event emitted by one session at one instant.

Strongest rejection — the daemon + SQLite the draft proposed, cut on S2's measurement and on failure mode. Also rejected: a git-ignored store (does not survive a clone) and a shared record file — the latter not because appends interleave (S3 proves they do not) but because per-session files make authorship reviewable in a diff.

ADR-0008

Identifiers from a non-coordinating stdlib scheme — not uuid7, not scanning

48-bit ms timestamp + 80 bits of os.urandom, Crockford base32. Serves the repository's existing registers; expand-migrate-contract, every existing id keeps its value.

Strongest rejection — uuid.uuid7(), rejected on execution (S1). Branch scanning rejected as a design: it shrinks the collision window from "any two sessions the same day" to "any two sessions minting within the same few minutes", and not to zero. Renumbering rejected because it would touch merged commit subjects and PR bodies no edit can reach.

ADR-0009

Artifact class decides the mechanism; derived artifacts are regenerated, never leased

A committed, PR-reviewed class registry; a .gitattributes merge driver for derived artifacts, proven in S6 to resolve cleanly while an authored file on the same merge still conflicts.

Strongest rejection — a uniform lease (the draft), which aims the mechanism at 13/60 and misses 58/60. The post-hoc regeneration script is partially superseded, not dismissed — it works, but it acts after the conflict exists and only when someone remembers; its hardening is carried forward as requirements.

ADR-0010

Enforce at the edit boundary where it exists, at the commit boundary always — fail to ask

PreToolUse returning permissionDecision; pre-commit as the floor no settings key removes; exec-form args with no shell.

Strongest rejection — failing open when lease state cannot be determined, rejected on the recorded evidence of a guard that failed open and a control that accused its own branch on CI. Also rejected: advisory-only (the corpus is a list of correct warnings that changed nothing) and a shell-string hook command (exec-form closes SHELL-A structurally).

ADR-0011

Cross-agent content is untrusted data; the projection ships only after its rendering rules exist

Length-bounded, structurally delimited, rendered under an explicit untrusted heading, never interpolated. Delivery order inverted so the projection is Phase 4, gated behind its own design.

Strongest rejection — shipping it early because it is the most visible feature. It is the most visible and the only in-scope capability that creates a new attack path. Sanitising by stripping instruction-shaped phrases also rejected: a denylist of phrasings fails silently on the phrasing nobody listed.

ADR-0012

Compose what already exists — and name what is retired

The reconciliation the spec made a condition of pass, plus the exact git expression for unique work and why the intuitive one silently reports SAFE.

Strongest rejection — writing the layer from the spec alone, which would have rebuilt two mechanisms the harness already ships. Keeping the existing scripts alongside the layer also rejected: two answers to one question is the defect signature.

Cross-cutting concerns

Designed in, not deferred — with what each failure degrades to

FailureBehaviour
Record unreadable or absentNOT CHECKED, advisory, said out loud
Session dies holding leasesTTL expiry — and the expiry is an event in the stream, not an absence
Clock skew, or a clock that moves backwardsSkew bounded by TTL. A backwards clock shortens a lease — the safe direction. Ids unaffected (80 random bits)
Detached HEAD — the state every PR gate runs inExplicitly handled: symbolic-ref fails and is expected to; the reachability check is local-only and declines on CI, where "does my work exist anywhere else?" has no meaning
Hooks disabled by policyDetected; layer reports advisory; the commit floor still holds
Merge driver unregisteredDetected by read-back; reported, never assumed

Idempotency. The fold is a pure function of the record — replaying twice yields identical state, and that is the property it is tested on. Every verb is idempotent by identifier, which matters because a hook may run twice on a retried tool call.

Observability. The record is the telemetry. All four metrics derive from it plus git: conflicts per merged PR, % of edits under a held lease, wait on a refused claim, and commits reachable from exactly one ref. A refusal is an appended event, not just a string returned to one agent — otherwise the most interesting thing the system does would be invisible.

Delivery — defined whole, phased vertically

Each phase deployable, human-demonstrable, test-validated. Mocked seams are contracts.

PHASE 1
skeleton

One refusal, end to end

Real: record, fold, CLI (claim / check / release / tail), authored class only. Mocked as contracts: the class registry is a two-line literal; no hook, no allocator, no merge driver, no projection.

Demo: two terminals, two worktrees. A claims src/**; B claims src/Foo.cs and is refused with holder, reason, remedy in four lines; A releases; B is granted.

Tests: claim/refuse/release/expiry · fold idempotence (replay twice → identical state) · the LOG-A seam (append onto a file with no trailing newline → two parseable records, not one fused line) · an empty corpus reports "0 events", never "clean".

PHASE 2
enforce

Claude Code enforcement + the work-preservation guard

Real: the PreToolUse hook in exec-form with the if pre-filter (the S5 program is already written); pre-commit floor; the reachability guard with the S4-verified expression; one-session-per-worktree. Mocked: other harnesses stay advisory and say so.

Tests: the five hook cases in CI · the guard proven on the un-fixed shape — rev-list HEAD --not --all must be shown returning SAFE for a branch holding exactly one unique commit before the fixed expression is trusted · a single at-risk commit is counted · detached HEAD declines rather than accuses.

Unblocks the % of edits under a held lease metric — the number that decides whether enforcement works at all.

PHASE 3
structural

Allocation + derived merge — the two structural fixes

Real: the allocator serving this repo's own audit and change logs; the .gitattributes driver and class registry; registration read-back. Plus the Copilot and third-harness hook spikes that close the rest of F1.

Demo: two worktrees mint an id in the same second and get different ones; two branches regenerate the docs index and merge with no conflict, while an authored file on the same merge still conflicts normally.

Tests: the S1b burst — asserting 4,000 ids were actually issued before judging uniqueness · the entry-count conservation assertion, proven red on a dedupe-by-id resolution · the S6 driver test including the fail-closed case outside the declared set.

PHASE 4
gated

Decisions, projection, operator surface

Real: the decision register with decisions returned with the grant; the projection under 2k tokens; the operator status view.

Gate: the STRIDE pass below is complete and its mitigations implemented before a single projection is rendered. That ordering is why the projection is last rather than first.

STRIDE on the projection boundary

The one boundary that did not exist before this layer — opened here, closed in /design

S5 named the exact channel while establishing the hook contract: hookSpecificOutput.additionalContext, described as "text injected into model context." The mechanism that makes a refusal actionable is the same mechanism that makes an injected instruction actionable. This is a live path, not a theoretical one.
