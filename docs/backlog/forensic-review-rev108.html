FR-086 · risk · P2 — Hook byte-code cache in a fixed directory under shared temp

  • Location: pack/adapters/hooks/dispatch.py:142.
  • Evidence: sys.pycache_prefix = os.path.join(tempfile.gettempdir(), "ai-forward-pycache").
  • Consequence (Inferred): on a multi-user POSIX host /tmp is shared. Another user can

create ai-forward-pycache first and plant .pyc files that the hooks then import. A Windows temp directory is per-user, so the exposure is POSIX only.

  • Remediation: a per-user, owner-only directory (for example under

$XDG_CACHE_HOME or ~/.cache, created mode 0700 and verified owned by the current uid), or sys.dont_write_bytecode = True in hook processes.

  • Acceptance: a test pre-creates the directory as foreign or world-writable and asserts the

hook refuses to use it.

  • Owner: Security & Identity. Next skill: /implement.
  • Resolved 2026-10-19 (revision 114). The cache is $XDG_CACHE_HOME/ai-forward/pycache (else

~/.cache/…), created 0700. On POSIX it is refused unless it and its parent are directories owned by the current uid with no group or other write; with no usable cache no byte code is written. BytecodeCacheIsPrivate plants a world-writable directory at each level (POSIX runners; Windows profiles are per user) and was observed red (AttributeError) first.
