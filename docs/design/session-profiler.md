# Design: session profiler

- **Status:** Accepted
- **Spec / architecture:** the profiling pass that produced revision 60 (`docs/profiles/sp-0001`), `docs/architecture.md`
- **Delivery phase / vertical slice:** Pack-evolution slice 3. Deployable — `docs/ai-forward-pack/scripts/session-profile.py` lands in installed repos; the `/session-profiler` skill drives it.
- **Author(s) / date:** AI Systems Engineer + SRE + Simplifier, 2026-09-05

## Responsibility
Turn *"the session felt slow / expensive / drifty"* into a measured, cited finding with the pack surface that owns its control. One script, three views: **profile** (per session, per turn), **compare** (model family × harness), **fixes** (the catalog). It never judges intent — heuristics over text are labelled *Inferred* and the skill confirms them against the transcript.

## Contracts
- **Exposed:** `session-profile.py --repo <path>[ --repo …] [--days N] [--harness all|copilot|claude] [--session id…] [--limit N] discover | profile [--out-root] [--json-only] [--session-id] | compare | fixes`. Exit 0 on success, 1 when no session matches, 2 on usage error. Output: `docs/profiles/<sp-id>/profile.json` (canonical), `profile.md` (V2 frontmatter, `relates-to` this design - a graph node), a row in `docs/profiles/PROFILES.md`, an audit entry via `audit-log.py`.
- **Consumed (established from the stores themselves, not documentation — RIG-D):**
  - Copilot CLI 1.0.83: `~/.copilot/session-store.db` — `sessions(id, cwd, repository, summary, created_at, updated_at)`, `assistant_usage_events(turn_index, agent_id NULL=main, model, input/output/cache_read/cache_write/reasoning tokens, total_nano_aiu, duration_ms, time_to_first_token_ms, …)`; `session-state/<id>/events.jsonl` — `user.message` (delivery idle/steering = human; queued = parent→sub-agent), `assistant.message`, `tool.execution_start/complete` (interactionId attributes tools to a conversation), `subagent.started/completed`, `system.message` (the prefix, `<custom_instruction>` blocks), `hook.*`, `abort`, `session.error`. *(Verified on a captured 4,700-event stream.)*
  - Claude Code 2.1.x: `~/.claude/projects/<slug>/<session>.jsonl` — `user`/`assistant` records (`isSidechain` = sub-agent), `message.usage` (input, cache_read, cache_creation, output, thinking), `tool_use` blocks, `ai-title`, `cost-state`. The project slug is the absolute path with every non-alphanumeric character replaced by `-`. *(Verified on this repo's own transcripts.)*
- **Not recorded (and said so):** Claude Code TTFT and the system prompt; Copilot per-turn USD. `context-budget.py prefix` is the offline estimate for the prefix; the profiler reads the real one only where the harness stored it.

## Patterns
- **Instrument, don't infer** (IO1/IO5) — the whole design. Named in code `# instrumentation over inference`.
- **Detector catalog with stable ids** (SP-xx → F-xx) so `/dream` can mine recurrence across profiles and `/apply-learnings` can push a fix by id. Rejected: free-text findings — un-minable.
- **Fail-open readers**: a broken or missing store is reported per session and skipped; nothing is estimated around it (IO8).
- **Attribution by the log's own field** for Copilot: every sub-agent event (its `user.message`, `system.message`, `assistant.*`, `tool.*`) carries a top-level `agentId`; main-conversation events carry none. A human turn is a main `user.message` delivered `idle` or `steering`; a `queued` or delivery-less main message is a parent→sub-agent message. Established on the captured stream after two positional rules (parent-id chains, event ordering) were falsified against it — the chain is linear and parallel sub-agent starts interleave. `simplify:` a message with no `delivery` value is never treated as a human turn — upgrade trigger: a harness release that changes the delivery vocabulary.

## Failure modes
| Mode | Disposition |
|---|---|
| Store schema changes (column renamed) | **detect** — the session is skipped with the exception named on stderr; the profile says how many were skipped |
| Two harnesses record the same session differently | **accept** — metrics are normalised per turn, and per-field `not recorded` marks what a harness lacks |
| A heuristic (goal-state regex) misfires | **mitigate** — labelled Inferred; the skill's Stage 2 confirms against the transcript before it enters the fixes table |
| Prompt fragments carry a secret into a profile | **mitigate** (revision 115) — every string in a profile is scrubbed with `dream.py`'s patterns before it is printed or written, and the profiler refuses to write if the scrubber is missing (FR-103, `NoSecretReachesAProfileTests`). Outside the pack source repository a profile stays in the untracked `<git-dir>/ai-forward/profiles/` unless `--publish` is passed, and the run prints where it went (FR-104, owner ruling 2026-10-19). Residual: the scrub is a pattern list; a secret in no known shape still passes |
| Huge stores (100 MB transcripts) | **accept** — linear single pass per file; `--days`/`--limit` bound the window |

## Test plan
`tests/docs_explorer/test_session_profile.py` — synthetic Copilot store + events (double-loaded prefix, 3× re-read, skill re-invocation, runaway sub-agent + converge nudge, orientation read, harness nudge, TTFT 25 s) → SP-02/04/05/07/08/10/11 with the planted evidence; a clean fixture produces none of them; a Claude transcript parses into turns with `not recorded` where the harness lacks the field; missing stores → exit 1; catalog integrity (every finding maps to a known fix); markdown render carries the three tables.

## Conformance notes
Runs under `python3`/`python`/`py -3` (INSTALL §0); utf-8 stdout reconfigured (FR-047 class); read-only SQLite URI; no third-party imports.

## Flagged risks
- The model-family comparison is only as good as the turn mix — SP-14 carries a caveat and the skill requires ≥3 comparable turns per family before tuning.
- Claude Code sub-agent attribution relies on `isSidechain`; an agent run through a different mechanism (a remote session) would count as main.

## Adversarial analysis (STRIDE-lite)
Trust boundaries: (1) harness telemetry written outside the repo by Claude Code and Copilot CLI → `session-profile.py` → committed files under `<out-root>/docs/profiles/`. The stores are `~/.copilot/session-store.db`, `~/.copilot/session-state/<id>/events.jsonl` and `~/.claude/projects/<slug>/*.jsonl`; `COPILOT_HOME` and `CLAUDE_CONFIG_DIR` can redirect them (`copilot_home`, `:619-620`; `claude_home`, `:917-918`). This telemetry is **untrusted content**: it holds every prompt, tool command and tool result, including text from fetched pages and files. (2) Each `--repo` path → the `git` and `audit-log.py` processes the profiler runs there. **T (tampering):** the SQLite store is opened read-only (`_ro`, `mode=ro` URI, `:631-632`) and transcripts are opened for reading only. The profiler writes only `docs/profiles/<sp-id>/profile.{json,md}` and appends to `PROFILES.md` (`cmd_profile`, `:1898-1930`; `_index`, `:1932-1950`). No test checks that the stores are unchanged after a run. Malformed lines are skipped (`_load_events`, `:660-671`), which is fail-open by design (IO8). **S (spoofing):** a session is attributed to a repo by the store's own `cwd` and `repository` fields (`in_repo`, `:606-616`) and by Claude's directory slug (`claude_slug`, `:600-603`). A session that recorded another repo's cwd, or a remote with the same `owner/name`, is counted as this repo's. Accepted: a profile is a measurement, not an authorization. No test covers misattribution across repos. **R (repudiation):** each run appends its own audit entry through the repo's `audit-log.py` (`_audit`, `:1954-1973`). A failure there is swallowed (`except … pass`), so a run can leave no audit row. Accepted under IO8. **I (information disclosure):** **not mitigated — the live threat.** The script copies session content into the committed tree without scrubbing it. That content is: the first 160 characters of every human prompt (`:752` Copilot, `:1101` Claude); up to 90 characters of each piped-gate shell command and each failed heredoc result in the SP-24/SP-25 evidence, which also lands in each turn's `shell_shapes` in `profile.json` (`shell_shape_counts`, `:288-304`, fed by `:1042` and `:1168`); session titles; cwd paths; and re-read file names. The whole line is kept, not only the gate segment. A command such as `export GH_TOKEN=ghp_… && pytest … | tail` is written to `profile.json` and `profile.md` as typed (**Verified 2026-10-19**: `shell_shape_counts` given `export GH_TOKEN=ghp_PLANTED… && python -m pytest tests -q | tail -5` returned the evidence line `gate piped: export GH_TOKEN=ghp_PLANTED…` with the token intact; FR-103. A pattern scan of the 8 committed profiles found no token, key or password). `session-profile.py` has no scrub pass. The regex scrubber is in `dream.py` (`scrub`, `:81-89`) and runs only on what `/dream` mines, after the profile is already on disk. **The design and the code disagree:** the failure-mode table says "profiles are committed only after the skill's review", but `pack/commands/session-profiler/SKILL.md` has no secret-review step. Its Stage 4 strikes findings that are not useful; it does not review their content. No test pins the 160-character truncation or the absence of secrets (`tests/docs_explorer/test_session_profile*.py`). Untrusted transcript text also reaches the model that reads `profile.md` in Stage 2. That is a prompt-injection path into the fixes table; the only mitigation is the human gate. **D (denial):** each file is read in one linear pass, and `--days` and `--limit` bound the window. The Claude title sniff stops after 400 lines (`:938-939`), but `_load_events` still loads a whole transcript into memory. Accepted, per the failure-mode table. Git calls time out at 20 s (`git`, `:557-565`) and the audit append at 30 s (`:1964-1970`). **E (elevation):** **accepted, not stated before this section.** The profiler executes the `audit-log.py` it finds in the output repo (`docs/ai-forward-pack/scripts/` or `pack/scripts/`), with `sys.executable` and no `-I` (`_audit`, `:1958-1966`). It also runs `git rev-parse`, `git worktree list` and `git remote get-url` inside every `--repo` (`repo_identity`, `:568-583`), so that repo's `.git/config` applies. Profiling a repo therefore runs that repo's code with the operator's privileges. This is acceptable only because the operator profiles pack-consuming repos they already work in. No test. Negative tests: `test_missing_stores_report_nothing_found` (exit 1, nothing estimated) and `test_it_tolerates_the_empty_and_missing_cases`. Untested: the read-only store, truncation and secret absence, misattribution across repos, and code execution from the output repo.

**Revision 115 update (2026-10-19):** the disclosure threat above is now mitigated. `cmd_profile` scrubs every string (`scrubbed`, using `dream.py` `scrub`, which gained `github_pat_` and private-key patterns) before `--json-only`, both files and the index, and returns 2 without writing if the scrubber is missing. Outside the pack source repository profiles default to the untracked `<git-dir>/ai-forward/profiles/` (`profiles_dir`). Pinned by `NoSecretReachesAProfileTests` and `ProfilesStayLocalOutsideThePackTests`, both observed failing first. Residual: pattern-based, so a secret in an unknown shape passes.

## Privacy analysis (LINDDUN-lite)
| Data flow / category | LINDDUN finding | Disposition | Control / rationale | Retention & rights path |
|---|---|---|---|---|
| Harness stores → profiler (read) | D: reads the human's prompts, assistant text, tool calls and file paths from `~/.copilot/session-store.db` + `session-state/<id>/events.jsonl`, `~/.copilot/settings.json`, `~/.claude/projects/<slug>/*.jsonl` and their `subagents/agent-*.jsonl` + `.meta.json` | mitigate (partial) | Read-only: SQLite opened `mode=ro` (`session-profile.py:_ro`); JSONL opened read-only (`_load_events`, `read_subagents`). Assistant text and reasoning are measured as character counts only (`profile_copilot`, `profile_claude`) and never copied out. | Source stores are the harness's; the profiler never writes or deletes them. |
| Turn prompt → `profile.json` / `profile.md` | I/D: the human's verbatim prompt, truncated to 160 chars (`profile_copilot`, `profile_claude`); 60 chars of it are re-quoted in finding evidence (`detect`) and 48 in the markdown table (`render_markdown`) | accept (owner ruling) | Truncation is the only minimization. **There is no redaction or secret scrub in `session-profile.py`.** | Committed under `docs/profiles/<sp-id>/` and served on Pages (`docs/profiles` is not in `tools/build-pages-bundle.py` `LOCAL_ONLY`). Git retention; the only rights path is a history rewrite (`git-filter-repo`) plus a Pages redeploy. |
| Session metadata → profile | L/I: session id, harness title/summary (`sessions.summary`, Claude `ai-title`), absolute `cwd`, absolute `--repo` paths (`cmd_profile`): home directory and other repository names | accept (owner ruling) | None; paths are emitted unshortened. | as above |
| Tool calls → profile | D: full paths of files read 3+ times and of instruction files (`rereads`, `instruction_views`); basenames of sub-agent orientation reads; Claude sub-agent task descriptions (`read_subagents`); **shell command text (≤90 chars) for gate-behind-pipe lines and tool-result text (≤90 chars) for failed heredocs** (`shell_shape_counts`) | accept (owner ruling); command and tool-output fragments are a data class the ruling does not name | Truncation only. | as above |
| `docs/audit/audit-log.jsonl` → compile section | L: per-session compile measurements (`compile_measurements`) | accept | Numeric aggregates and ids, from a store that is already committed. | The audit log's own retention. |
| `--repo A --repo B` → `A/docs/profiles` | D: session data from repository B is written into repository A (`cmd_profile`) | accept (owner ruling, re-open trigger 2) | None; the operator chooses the repos. | A's Git retention. |

Linkability is by design: a profile joins one session's turns, paths and costs so `/dream` can mine recurrence across profiles. Non-repudiation and detectability add nothing beyond what the source stores already record. **Unawareness:** the skill does not tell the operator that the output carries prompt text, paths, command lines and tool-output fragments, or that `docs/profiles` is published (GitHub Pages in this repository; whatever the consuming repository's visibility is elsewhere). **Non-compliance:** this repository's publication is the owner's recorded decision (`note-20261017-session-profiles-published`); that ruling binds this repository, not consuming repositories that run the deployed script. **Egress:** none by the script. It imports no network module, and its only subprocesses are local `git` and `audit-log.py`. `--json-only` prints the whole profile to stdout. The skill's Stage 2 has the model read the transcript to confirm Inferred findings; that transcript goes to the harness provider that produced it, so no new third party is involved. The failure-mode row that said profiles "are committed only after the skill's review" and that "`/dream` scrubs every note it mines" described protections profiles do not get; it is corrected above to *accepted per the owner ruling* (privacy review, 2026-10-19).

**Revision 115 update (2026-10-19):** the disclosure threat above is now mitigated. `cmd_profile` scrubs every string (`scrubbed`, using `dream.py` `scrub`, which gained `github_pat_` and private-key patterns) before `--json-only`, both files and the index, and returns 2 without writing if the scrubber is missing. Outside the pack source repository profiles default to the untracked `<git-dir>/ai-forward/profiles/` (`profiles_dir`). Pinned by `NoSecretReachesAProfileTests` and `ProfilesStayLocalOutsideThePackTests`, both observed failing first. Residual: pattern-based, so a secret in an unknown shape passes.
