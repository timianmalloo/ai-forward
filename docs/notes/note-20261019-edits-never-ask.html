Decision — an edit never asks for permission

Date: 2026-10-19 · Decided by: the owner · Executed: revision 114 (coord-core.py)

The ruling

The owner, in session: "I should not have to give permission for edits … when I run in bypass permissions or some form of YOLO the asking for permissions gets in the way … so ensure that on edits I DON'T have to provide permission."

What the hook answers on the Claude host

ConditionAnswerEffect
Checked, and the path is free or under your own leaseallowNo prompt in any mode

Not checked: no AGENT_SESSION, no coordination record, an unreadable record or payload{}The session's mode decides

ask is not among the answers. Claude Code prompts on a PreToolUse ask even in bypass mode, so before this ruling every "not checked" condition prompted on every edit. That covers any consuming repo with no coordination record. Codex, Grok, Antigravity and Copilot keep their recorded fail-closed deny (FR-100 tracks the cost).

Why {} and not allow for "not checked"

allow would be a grant the hook did not earn: with no record or no identity it cannot know whether the path is leased. {} adds nothing. In bypass mode there is no prompt; in default mode Claude Code prompts as it would with no pack installed. That is the user's own choice of mode, not the hook's.
