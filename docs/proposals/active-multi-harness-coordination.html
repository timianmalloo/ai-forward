The ledger is not a bus

Git, githooks, and the append-only fold are the right substrate for leases and accountability. They are the wrong substrate for liveness. This proposal adds an optional local bus, and — when sessions do not share a filesystem — an optional cloud relay. GitHub stays defense in depth: every kick still lands in the git-tracked ledger.

Thesis

The pack already built the right ledger. AI-DE already built the live surfaces of a bus — and they stayed empty, because every path is a pull the agent may ignore.

Git, githooks, PreToolUse, pre-commit, and an append-only JSONL fold give concurrent agents leases, collision-proof ids, derived-file regeneration, and an audit trail. That layer answers may I touch this file? and what was decided? It does not answer the other session is stuck — tell it, and if it does not move, take the work.

GitHub and githooks are eventual. A claim is visible after a push and a fetch, or after the next edit-boundary check. A blocked-on edge is a fold, not a message. A stalled session expires a TTL and is discovered by whoever happens to claim next. Nobody is responsible for chasing progress. That is the passivity.

Keep the ledger as the source of truth. Add an optional, local-first message bus for liveness. Dual-write every coordination act to the ledger so accountability survives the bus going down. Elect a Leader among sessions so someone is on the hook for the whole work list. Inside a session, name Owner / Conductor / Worker so the most capable model decides and the right-sized model executes.

If the bus is down, the existing layer still works — slower, the way it works today. That is NFR-P2, kept. Canonical record: active-multi-harness-coordination.md.

01

Diagnosis — the ledger is correct and too quiet

Phases 1–4 already close four measured modes: structural conflict on derived files (M1), allocation collision (M2), silent divergence (M3), and work loss in a shared tree (M4). The substrate decision still holds: append-only JSONL, one file per session, folded on demand, no daemon, no database (ADR-0007). Spike S2 priced a 10,000-event fold at 47 ms p95 against a 100 ms budget.

What git and hooks cannot see

ModeWhat happens todayWhy git/hooks cannot fix it
M5 Stall A session is alive, holds leases, and is not making progress. TTL expiry is the only recovery, and it is silent. A hook fires on edit, not on absence of edit.
M6 Passivity Session B records blocked-on: A. A does not find out until it folds, fetches, or happens to coord tail. Git is pull. There is no push to a running model.
M7 No hierarchy Every session is a peer. Decisions that should be made by the strongest model wait for a human, or get made twice. The session contract has roles as prose. Nothing elects, nothing delegates as a protocol.
M8 No kick Nobody is accountable for the fleet’s work list. A blocked waiter waits. A looping worker loops until a human notices. The operator view is a query. It is not a supervisor.
M9 Cross-harness liveness Copilot, Grok, Claude Code, and Antigravity share a git remote and a JSONL directory. They do not share a live channel. Each harness’s hook surface is an edit interceptor, not a mailbox.

The architecture already recorded the delay that makes this worse: the gate delay exceeds the merge interval, and the push delay is the window a branch scanner cannot see into. The allocator was designed for that window. The lease was designed for the gate delay. Nothing was designed for “the other agent is in another process, on another harness, and needs to be told now.”

02

What we keep

ADR-0007 cut the daemon because the fold met the latency budget, because a required service makes “the agent cannot work until the service is up” a new failure mode, and because for a control whose recorded ancestors failed by reporting success, a loud non-blocking failure is worth more than 20 ms.

Those three reasons still hold for grants and refusals. The bus is a transport, not a store:

  • Every message that changes coordination state is dual-written to the session’s JSONL.
  • The fold remains the only source of leases, work-item status, blocked-on edges, and leader identity.
  • If the bus is down, the layer says so and degrades to today’s pull-based behaviour. It does not refuse work because a socket is missing.

The Enterprise Architect’s existing ruling is kept verbatim: if a planner is added later it may advise, never grant or refuse. The Leader and the Conductor advise, delegate, and kick. The ledger still grants and refuses.

03

Research — what to steal, and what not to

Lab multi-agent systems

Anthropic (June 2025). Orchestrator-worker. Opus 4 lead + Sonnet 4 subagents beat single-agent Opus 4 by 90.2% on their internal research eval. Token usage alone explained 80% of BrowseComp variance. Multi-agent runs use about 15× the tokens of a chat — the pack already encoded this as GO6. They also recorded the production failure that matches M5/M6 exactly: the lead agent executes subagents synchronously, cannot steer them, and can be blocked waiting for one of them. Copy two tactics: teach the orchestrator to delegate with an objective, output format, tools, and boundaries; and have subagents write artifacts to the filesystem and return a reference, not a novel.

Magentic-One (Microsoft, 2024) and Magentic-UI (2025). A lead Orchestrator runs two loops. The outer loop owns a Task Ledger (facts, guesses, plan). The inner loop owns a Progress Ledger (current assignment, “is progress being made?”). If the stall count exceeds two, the outer loop replans. That is kick-and-replan as a control loop. Magentic-UI then put a human on the team as UserProxy — the Owner in this proposal is that seat, occupied by the strongest model until it must escalate.

The 2026 protocol stack has split. Do not smash the layers.

LayerProtocolJobOur mapping
Agent ↔ tools MCP (Anthropic → LF Agentic AI Foundation, Dec 2025) Call tools Existing coord CLI; future MCP host over the same core
Agent ↔ editor ACP (Zed, Aug 2025; JetBrains co-maintains; v2 draft Jul 2026) Drive a coding session inside an editor Out of scope. We do not become an IDE.
Agent ↔ agent A2A (Google, Apr 2025; Linux Foundation; v1.0 Mar 2026; 150+ orgs) Discover, delegate, converse across vendors The bus’s public shape, later. Session Cards should be able to become A2A Agent Cards.

IBM’s Agent Communication Protocol merged into A2A (archived Aug 2025). Do not mint a fourth wire format. Local v1 can be JSON lines over a Unix socket; the schema of a Session Card should be A2A-shaped so the adapter is a rename, not a redesign.

Anthropic’s own caution, which the pack already believes: most coding tasks have fewer truly parallelizable pieces than research, and models are not yet great at coordinating in real time. The same post records that subagent waves still run synchronously — asynchronous subagents are future work. That is M5/M6 at the lab that invented the pattern.

Two topologies, not one. AutoGen ships SelectorGroupChat (central), Swarm (HandoffMessage, the specialist becomes the active agent), and MagenticOneGroupChat (stall-counter Orchestrator). OpenAI’s Agents SDK makes the same fork first-class. AgentPlane is manager-retains-control. Independently launched Copilot/Grok/Claude sessions are the Swarm shape. The elected Leader is how a Swarm grows a Magentic-One inner loop without requiring every participant to have been spawned.

A2A is not a P2P control plane. v1.0 is client–server; push is optional, capability-gated, server-initiated, and one-way. ANP is the closer cousin: Profile P3 requires the peer-initiated notification direct.incoming. AGNTCY’s invocation ACP was archived April 2026. Session Cards stay A2A-shaped; v1 behaviour (mandatory notify on blocked/kick) is the ANP lesson.

The distributed-systems theorem behind Q7. Raft’s leader pushes heartbeats; followers do not poll. Chubby’s API was built around event notification specifically so clients need not poll files. CRDTs converge only after eventual sync — they are not an active coordination protocol. The 8,143 s wait is what you get when the control plane is a file the agent may choose not to read.

Agent-native repositories

Zed Delta (public beta 16 Sep 2026) is the sharpest “replace GitHub” attempt in this window. They disabled pull requests on Delta’s own repo and landed 570 changes to main from 33 people. The unit of work is a thread (conversation + edits + worktrees + review), not a PR. DeltaDB extends Git with incremental deltas between commits so the reasoning is not thrown away at git commit. They still keep Git as the checkpoint you build from, and they still use GitHub for community contributions to zed-industries/zed.

Steal the live thread. Do not steal replacing PRs or standing up a CRDT database as the source of truth. Our ledger already is the conversation-about-intent; Git already is the checkpoint. The missing piece is the live thread between harnesses that are not Zed.

CodeCRDT (Pugachev, arXiv:2510.18893): observation-driven coordination on a CRDT, 600 trials, zero merge failures, up to 21.1% faster on parallelizable tasks and up to 39.4% slower on coupled ones, with 5–10% semantic conflicts the CRDT cannot see. Independent confirmation of GO5 and ADR-0009. Do not put source files on a CRDT. A CRDT of presence and work-item state is a plausible read-model for the bus.

AgentRoom (2026) makes the same split we want: CRDT for the filesystem plus explicit file-level claims. GitButler vcbench and Jujutsu are a better agent VCS UX on top of Git; they do not coordinate two harnesses. Mentioned so we do not “solve” VCS UX in this proposal.

Classic P2P — the hybrid that survived

SystemStealRefuse
Napster A directory is fast. Use one as bootstrap (the Leader). The directory as the only path. If the Leader is down, peers must still find each other from the ledger.
Gnutella Membership must be hierarchical or the cheap nodes drown. 50% of early traffic was pings. Flooding heartbeats. Five to twenty local sessions do not need a DHT; they do need to not ping-flood.
JXTA The vocabulary: advertisements, peer groups, optional rendezvous, pipes, resolver. Implementing JXTA. Steal the concepts, ship JSON.
BitTorrent Work items as pieces. Rare-first = serial spine first. Tit-for-tat = finish-and-release. Optimistic unchoke = give a stalled session a small piece to restart. Treating source files as pieces of a blob. Artifact class already says which contention is real.
Chubby / etcd Leader is a lease, not a personality. Sequencer token. Heartbeat renewal. Building a Raft cluster for five local processes.
Phi-accrual Stall ≠ dead. Two detectors: liveness-φ (heartbeats) and progress-φ (work-item events). A single TTL for both “process died” and “model is looping.”
CRDTs Fine for presence sets and the operator view. Not for authored source. Not a replacement for the fold.

The hybrid that actually survived in P2P history is Napster’s transfer path plus BitTorrent’s tracker-as-bootstrap plus JXTA’s advertisements. Centralised enough to be fast, decentralised enough to survive the centre dying, with a published card so other harnesses can find you without a prior handshake.

P5–P7 are loopback only. The relay (P8) leaves loopback and requires signed Session Cards. Unsigned asserted identity (ADR-0011) must not be accepted on the wire. A GitHub token may authenticate the operator to the relay; it is not the session’s identity. Bus payloads stay data, never instruction.

05

In-session: Owner, Conductor, Worker

Seat 1

Owner

Most capable model available to the session. Decides architecture, scope, and “is this done.” Reduces human interaction by taking decisions the mandate covers. Escalates when it does not. Must not grant leases or quietly expand the goal.

Seat 2

Conductor

Highly capable model; may be the same process as Owner. Decomposes, assigns, joins, watches progress-φ, sends delegate/kick inside the session, and stands for Leader between sessions. Must not do the Workers’ jobs by default, and must not spawn unbounded subagents.

Seat 3

Worker

Right-sized model for the task. Executes one assignment against owned paths. Writes an artifact and returns a reference. Must not re-plan the session or touch another Worker’s owned paths.

The Owner’s autonomy is the session contract’s “Accountable for” column plus a short written mandate at session start (goal, done-when, not-in-scope, decision rights). This is CT19 applied to the fleet.

Every delegate message contains all four, or it is incomplete: objective; output format / artifact path; tools and sources in bounds; boundaries (paths, fan-out cap, budget). The Worker writes the artifact to the worktree and returns a reference. The Conductor does not relay the Worker’s prose. That is Anthropic’s filesystem-not-telephone rule, and it is already pack doctrine that only the Conductor calls conductor-join.py.

06

Between sessions: a Leader that kicks

One Leader per peer group (the repo, or a named workstream). The Leader is a Conductor that holds an unexpired leader-claim in the ledger. Leader is a lease, not a personality. A sequencer (the claim’s event id) lets anyone verify that a kick came from the current Leader. If the Leader fails to renew, any Conductor may claim; first append wins; the fold is the total order — the same advisory-until-checked honesty as intersecting path claims.

Tie-break is not “highest model IQ.” Capability is advertised on the Session Card so a human can coord leader pin. Automatic ranking of model strings is a policy file if we ever want it; it is not the protocol. A wrong automatic ranking would elect a fast, shallow Leader — the failure Magentic-One avoided by putting the strong model on the Orchestrator.

The Leader is the fleet supervisor, not a second Owner of every session. It holds the work list, runs coord doctor as a periodic self-check, kicks when progress-φ crosses the threshold, reassigns after kick-without-ack, and unblocks waiters the moment a dependency’s done hits the bus. It may advise assignment. It may not grant a path lease.

The kick ladder

0

Notify

blocked-on recorded → bus delivers blocked to the holder immediately.

1

Kick

progress-φ ≥ threshold, or notify unanswered across one TTL → Leader sends kick with reason, suggested action (an enum, not a paragraph), deadline.

2

Reassign

Kick unanswered, or liveness-φ says dead → write the expiry as an event, then delegate to a capable idle session. That session still has to claim.

3

Owner

Reassign failed, or the work item is a decision not a task → escalate to the holding session’s Owner, or the Leader’s Owner if the holder is gone.

4

Human

Mandate does not cover it, or two Owner decisions conflict → stop. The operator view already exists; the bus pages it instead of waiting to be asked.

Caps: at most two kicks per work item per hour before rung 2. Progress-φ is computed from that session’s inter-progress intervals, not from a global “30 s of silence means dead.” A research session that heartbeats every turn and writes every five minutes is healthy. A coding session that claimed src/** and has not appended a progress event in the time it usually takes that session to edit is not.

BitTorrent, used lightly, for ordering only: rare-first (serial spine before leaf tracks), tit-for-tat (finish-and-release to get the next piece), optimistic unchoke (give a kicked session a smaller piece once before reassigning). Do not swarm the contents of a file.

All messages are JSON with kind, allocator id, from, to (* only for hello and leader-heartbeat), and a typed body. Broadcast is membership-gossip only. Work messages are directed. Idempotent by id.

Getting a message into a running model, in preference order: hook additionalContext on the next tool boundary — the push, reserved for blocked / kick / delegate and a count of new board posts, never for standing or board prose; the mailbox file, and when AI-DE is the host the Loomkeeper board + standing file that already exist (standing stays a pull); the Observatory for rung 4. Do not grow a third store: one ledger, projected.

Transport — stdlib, local-first, optional rendezvous

Unix domain sockets under .agents/bus/. No Redis, NATS, libp2p, MQTT, or sqlite in v1. Discovery is Napster-as-bootstrap locally. The cloud relay is the same rendezvous when a session cannot see the socket — Copilot’s cloud agent, a second laptop, a provisioned VM.

The relay is live path, not a second GitHub. It fans out presence and kicks. It does not grant leases. Dual-write first: JSONL then POST. If the relay and the fold disagree, the fold wins. A clone with relay: off is complete, slower. Stand it up only when a measured session cannot see .agents/bus/.

Local discovery:

  1. On SessionStart, write the Session Card to the ledger and to peers/.
  2. Try .agents/bus/rendezvous.sock. If it exists, register. If it does not, do not start it automatically. Full mesh is fine at N≤20.
  3. Git remains the discovery path across machines and after a reboot: fetch, fold, see cards.

That is JXTA rendezvous as an optimisation, not as a requirement. An agent can work the moment it has the repo. Windows falls back to named pipes or inbox-file-only; the ledger path is the portable one.

10

Open questions for the maintainer

The writer should not silently resolve these.

  1. Peer group grain. One Leader per repo, or one per workstream? Recommendation: per session-contract when one exists, else per repo.
  2. Owner and Conductor as the same process? Recommendation: yes, and that is the default. The protocol treats them as seats, not processes.
  3. Copilot. Wait for verified session-start + deny, or ship inbox-file-only? Recommendation: ship inbox-file-only, name it, do not wait.
  4. Auto-start coord bus serve from SessionStart? Recommendation: no. The first Leader claim may start it in-process; otherwise the operator does. Measure how often P5’s direct-mesh is enough.
  5. Automatic kick. Recommendation: P5 is notify-only. P6’s automatic kick is off until kick_ack_rate has a denominator (R4).
  6. Mid-turn abort? Recommendation: next tool boundary + mailbox. Mid-turn abort is Owner only, and it is a harness capability we do not have uniformly. Name it as residual.
  7. Push vs pull — does §1.6 hold? If the maintainer wants no injection of any kind, P5 degrades to “make the pull unmissable.” That still would not have unblocked the 8,143 s wait. Recommendation: keep the split — inject coordination, never inject scores.
  8. When does the cloud relay get built? Not until a session that cannot see .agents/bus/ is a measured participant. P5–P7 stay local. Hosting (Azure vs anything else) is operations. Dual-write and signed cards are the architecture. GitHub stays the remote either way.

Best next action. Decide Q7 (push vs pull) and Q1 (peer-group grain). Then /specify P5 against ai-de, not a toy repo. First demo: Copilot posts, Claude sees it on the next tool call, two launches get two worktrees. Q8 (relay) waits until a second host shows up in the profile.
