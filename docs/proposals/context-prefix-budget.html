Proposal · performance & context budget · implemented, rev 58

The 208K prefix is the whole problem

A profiled session in a repo that adopted the pack burned 161.9M input tokens across 484 calls, lost 27 of 39 delegated runs to a context ceiling, and spent 57% of agent time on reviews that changed nothing shipped. All three trace to one artifact: the always-on instruction set. It is 184,364 tokens, and it is re-read on every single call.

All eight parts shipped in revision 58. This page is kept as the reasoning record — the analysis that produced the change, not a pending plan. The profile is a colleague's three-page measurement of an Org Intelligence Portal session in a consuming repo; the pack-side figures were measured against ai-forward @ rev 57 and are restated below against what actually landed.

Measured result: the always-on set went from the whole corpus (~184,300 est. tokens, 39 docs) to 13 docs at ~43,700 — a 76% cut with nothing deleted, now held there by gate 8 of verify-bundle.ps1 and a required CI step. The widest sub-agent lens is ~29,500 (68% of the main thread's set); the Simplifier's is ~10,100 against a 208,434-token prefix before. Two figures moved from the estimates below: Tier A is ~43,700 rather than 42,747 (IO13 and GO19 were added to always-on docs), and the corpus total fell to ~171,400 after the LOA split.
63.3% of all main-thread input tokens were the static prefix, re-read. 484 × 208,434 = 100.9M of 159.3M.
27 / 39 delegated runs failed — every one on mai-code-1.1-flash, which was 0.1% of spend and 100% of failures.
37 / 39 knowledge docs ship with applyTo: "**" — loaded on every request, whatever the task.
77% of that set can leave the always-on tier without losing a directive, by scoping rather than deleting.

Three symptoms, one cause

01

The exhaustion was context, not spend

mai-code-1.1-flash consumed 10.7 AIU (0.1% of spend) and accounted for all 27 failures. A 208K unreclaimable prefix exceeds what a flash-class model can hold, so it failed at the cheapest tier precisely because it was the cheapest tier. Cost telemetry cannot see this failure mode; only the context ceiling can.

02

Cache is carrying the session, and hiding the cost

158.8M of 161.9M input tokens (98%) were cache reads. Without prefix caching this session is roughly an order of magnitude more expensive. But caching makes a 208K prefix survivable, not free — it is still billed on every call, and it still consumes the window.

Arithmetic added on review

484 main-thread calls carried 159.3M input tokens — 329K average per call, of which 208,434 is the static prefix. So 63.3% of every input token in the session was the same text, re-read. That is the multiplier every other number in the profile sits on top of.

03

The premium model was chosen at the least token-efficient moment

claude-opus-5 ran 211 main-thread calls and 76.6% of AIU — 3.6× gpt-5.6-sol's main-thread cost for fewer calls. The switch happened immediately before deployment: the most tool-heavy, highest-iteration phase, where every debugging loop re-reads the full 208K prefix at premium rates. The prefix and the model choice multiply.

Root cause: one line of PowerShell

The pack wraps every knowledge doc for Copilot-family harnesses as it syncs. The scope is hardcoded, with a single exception carved out for C#:

# tools/sync-pack.ps1:103
# Each knowledge doc is wrapped with applyTo frontmatter.
$applyTo = if ($kFile.BaseName -eq "csharp-style-guide") { '**/*.cs,**/*.csx' }
           else { '**' }
$header  = "---`napplyTo: `"$applyTo`"`n---`n"

applyTo: "**" means load this on every request. 37 of 39 docs carry it. The exception proves the mechanism already works — csharp-style-guide (7,515 tokens) is correctly absent from every non-C# call. Nothing else was ever given a scope.

Confidence — high that the knowledge set dominates the prefix; exact attribution unverified.

The knowledge set is 890,204 characters. It is the only pack artifact of the right order of magnitude: CLAUDE.md (6.1K tokens), agent definitions (25.2K) and skill definitions (82.5K) reach 113K together and cannot produce 184K. Across any plausible ratio (4.0–5.0 chars/token) the knowledge set alone lands at 178K–223K. Not verified: which files that harness actually loaded. A system-prompt dump from the consuming repo is step 1 of the sequencing — measure it, don't model it.

Four tiers, nothing deleted

The test for the always-on tier: a doc is Tier A only if an agent could violate it without knowing it exists. You cannot look up the no-guessing protocol when it becomes relevant, because not knowing it is relevant is the failure. You can absolutely look up the UI archetype catalog — you know when you are building a UI.

Eight changes, two of which carry the rest

#Change LeverageEffortWhere
P1 Give every knowledge doc a declared load scope. Frontmatter load: always | glob:<pattern> | skill:<names> | reference, read by sync-pack.ps1 instead of the hardcoded '**'. The enabling change — every other proposal here is currently unexpressible. XLS tools/sync-pack.ps1:103, 39 doc headers, pack/adapters/INSTALL.md
P2 Gate the always-on budget in CI. A tenth gate: sum the Tier A token estimate, print it, fail above a declared ceiling (45,000 — 5% headroom over 42,747). Without it the set silently re-grows. It also makes the budget a number emitted on the normal path, which is what instrumentation-over-inference asks of any feature. XLS tools/verify-bundle.ps1 — new context-budget gate
P3 Give sub-agents a lens-sized prefix, not the global one. Each agent declares the docs its lens needs. The Simplifier needs the solution-selection-ladder and no-guessing; it does not need the LOA catalog or seven UI docs. This is what makes cheap delegation viable again, and it targets the 27 failures directly. XLM .claude/agents/*.md (23 files) · depends on P1
P4 Split the two reference monsters into directive core plus evidence. layered-optimized-architecture is 19% of the payload in one file, and Part IV alone is a 15,958-token lookup catalog nobody reads linearly. The pack already does this — seven topics have evidence directories under docs/knowledge/. Extend the pattern rather than invent one. LM docs/knowledge/<topic>/ — pattern established at 7 topics
P5 Preflight the context ceiling before any fan-out. One failure at the ceiling predicts all 39. Compare the assembled prefix against the target model's window and fail fast — converting 23.6 minutes of burned agent time into a sub-second check. A new defect class with a control attached, as continuous-improvement requires. MS docs/lessons/defect-classes.md + a control in the dispatch path
P6 Yield-gate the advisory personas. The Simplifier (6 runs, 53.1 min) and Patterns Expert (4 runs, 33.2 min) took 57% of agent time and changed nothing that shipped; the four hard-veto personas took 24% and drove material change. Run advisory personas once, in one parallel wave; require an accepted finding to re-convene; record findings-accepted per persona so the roster is tuned on measured yield. LM persona-audit.md · audit-log.py schema · convening logic
P7 Bind model tier to phase, not to session. The premium switch landed exactly where iteration count is highest and novelty lowest. Deployment and debug loops want the cheap model with a small prefix; reserve the premium tier for design and adversarial reasoning. The pack allocates tiers already — it just never re-allocates them at phase boundaries. LS tier allocation in /define-architecture, /implement
P8 Record wall-clock spans per run, not just durations. The profile reports 67 runs totalling 152.6 min but only per-run durations — no start/end timestamps, which makes parallelism unmeasurable (below). A small addition to the audit entry, and the prerequisite for every parallelism claim the pack will ever make. MS audit-log.py — extends the existing duration_seconds field

The parallelism claim is not supported by this data

The profile states that 2h33m of agent execution is “more than the elapsed time, because adversarial reviews ran in parallel.” It is not: 152.6 minutes of agent time inside roughly 240 minutes of wall clock. Even fully serialised, that work fits. The published numbers therefore demonstrate no speedup at all.

That does not mean the fan-out did not happen — it means the measurement cannot show it. The comparison needed is agent time against the persona phase window, not the whole session, and the profile does not carry the timestamps to compute it. This is exactly the failure the pack warns about: an answer with no error bar and no way to be surprised. Hence P8.

Two more things to settle before these figures are quoted outward:

  • The AIU shares sum to 114.2%. The seven rows total 10,446.1 AIU, against which claude-opus-5's 7,003.6 is 67.0% — not the published 76.6%. The denominator is undocumented; main and sub-agent totals may be double-counting.
  • Sub-agent prefix size is unknown. gpt-5.6-sol sub-agent runs averaged ~114K input tokens against ~329K for main-thread calls, which suggests sub-agents already carry a smaller prefix. If so, P3's ceiling is lower than assumed and the flash failures need a second look. Worth resolving before sizing P3.

These are not trade-offs against each other. Trimming the always-on set cuts token volume, restores cheap delegation, and reduces premium spend simultaneously. There is no axis on which one is bought with another — which is what makes it the first thing to do rather than one option among several.
