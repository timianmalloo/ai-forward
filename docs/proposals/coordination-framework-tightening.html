01

What the CFD-Bench plan actually found

The plan is correct about CFD-Bench, and its own framing undersells it. It concludes “the layer ships inert by design; someone has to turn it on” and treats that as a repo-level setup task. I profiled 48 sessions across ai-de, cfd-bench and TheTerrace, then read coord-core.py, pack-apply.py, pack-doctor.py and verify-bundle.ps1 rather than recalling them. The setup task is not the finding. The finding is that no repo has ever been told to do it, and nothing anywhere notices that it was not done.

A control that ships uninstalled, with no step that installs it and no gate that detects its absence, is not a control. It is a library with good tests. The 49-test suite proves coord-core.py works; nothing proves it is running, and no test has a subject for that question.

This is the shape the pack already names for other people's code. It is now registered against the pack's own: CTX-H in docs/lessons/defect-classes.md.

03

The proposals

Ranked by benefit ÷ cost, not by section order

P1

The registry is derivable, not authored

best ratio

The CFD plan hand-wrote a registry and, in doing so, made the argument against hand-writing it: five of its six entries — docs/docs-index.js, docs/audit/audit-data.js, docs/audit/audit-log.jsonl, docs/audit/change-log.jsonl, docs/health-history.jsonl — are pack artifacts. They are byte-for-byte the same obligation in every repo the pack has ever been installed into. Asking each repo to rediscover them is asking each repo to repeat the same near-miss.

And the plan had the near-miss: it first wrote audit-log.py regen from inference. There is no such subcommand — it is render. A wrong regenerate command is worse than a missing entry, because the merge resolves silently and the artifact goes permanently stale while reporting as handled. The parser already refuses a derived entry with no command (coord-core.py:783); it cannot refuse one with the wrong command.

Add coord classify init: writes the pack's own derived/register defaults, executes each regenerate command once before writing it, and refuses to emit an entry whose command exited non-zero or left the tree dirty in an unexpected place. Repo-specific entries are appended by hand afterwards, under the same rule.

scripts/coord-core.py (new subcommand); INSTALL.md deployment map

coord doctor exits non-zero when a derived entry's command is unresolvable or non-zero — the near-miss becomes a red gate rather than a caught mistake

P2

Put the layer in the deployment map, and in the doctor

high

P1 is inert on its own for exactly the reason the whole layer is: something has to run it. Two additions, both mechanical.

Deployment map: a coordination step that runs coord classify init and coord install, and prints what it wrote. It must print rather than silently configure — coord install already follows that rule for the settings entry, and the same reasoning applies here.

pack-doctor: a coordination check. FAIL a repo that carries coord-core.py and no registry. WARN a clone whose .git/config lacks the merge driver — which is every fresh clone and every worktree, because .git/config is per-clone and never committed (coord-core.py:1779 says so in a comment, and coord doctor exists because of it; nothing routes a human to coord doctor at the moment a tree is created).

Control that fails on recurrence
pack-doctor FAILs the uninstalled state; the new gate FAILs a pack revision that ships a coordination change with no deployment step

P3

Stop printing a capability as a measurement

high

This is the pack's own instrumentation-over-inference rule pointed inward, and it currently fails it. coord doctor reads as a per-repo report; six of its lines are, and the harness lines are not — they are August spike results, identical in every repo forever. Worse, the honest half is now unreachable: the != "enforcing" branch that prints “the commit floor is the real enforcement for this harness” cannot fire, and plugin emit still prints the contradicting claim.

Three edits, none of them clever:

  • Move the harness lines under their own heading — capability (from spike S5 / 2026-08-24, not measured here) — with the date and the harness version they were established against, so a reader can see when they went stale.
  • Delete the unreachable branch and print the commit-floor sentence unconditionally: it is true in both states, and it is the sentence that matters.
  • Fix plugin emit to read from HARNESS_STATUS rather than restating a superseded conclusion in a string literal.

The version fields are the point. Copilot's deny contract was proven against CLI 1.0.80; TheTerrace's own probes have since exercised runtime 1.0.84-1. A capability claim with no version is a claim with no expiry.

scripts/coord-core.py — HARNESS_STATUS, cmd_doctor, cmd_plugin_emit
Control that fails on recurrence
a test asserting no doctor line mixes measured and constant state under one heading, and that the two surfaces render the same status string from the same source
Closes
G4, G5 — and one instance of HYG-A in the pack's own tree
P4

Retire hotspot until it has a mechanism

cheap

The CFD plan recorded hotspot as “not usable yet” so nobody plans around it. That is the right read and the wrong resting place: the parser accepts the class today. A repo that writes src/hot.cs: hotspot gets a registry that validates, a classify that returns hotspot, and merge behaviour identical to authored — with no warning anywhere. That is a success-shaped classification, the exact failure the pack refuses elsewhere.

Remove it from CLASSES. The parser then rejects it by the path that already exists, with the message that already exists. Reinstate it in the same commit that implements its merge behaviour.

P5

Bind the session to its tree, or record the exception where it can be counted

behavioural

Sixteen worktrees; not one profiled session ran inside one. WT4 permits the primary as a recorded exception — and an exception with no counter becomes the default, which is what the measurement shows has happened. The three overlapping pairs are the cost: two sessions sharing an index, a HEAD and one set of generated artifacts, which is the precise condition WT1 exists to prevent.

The cheap version, and the one I would build first: coord session start resolves whether the cwd is the primary or a registered tree and appends the answer to the coordination record. No refusal, no prompt, no friction — just a fact that a later pass can count. SP-15 already detects overlaps retrospectively; what is missing is the per-session datum that makes “how often do we take the WT4 exception?” a number instead of an impression.

Only once that number exists is it worth arguing about enforcement. Building a refusal first would be tuning from a feeling, which is the thing this whole exercise is against.

P6

The same gap exists inside a single turn

reframe

The CFD plan scopes coordination to sessions and worktrees. The measurement says the larger uncoordinated surface is inside one turn, and it fails in opposite directions on the two harnesses:

Family × harnessturnssub-agents drift / turnShape
anthropic / claude51520 1.06Delegates almost never — no fan-out to coordinate, and no parallelism where it would pay
anthropic / copilot47715 2.31577 re-reads and 149 cap firings dominate
openai / copilot131206 3.7416 fan-outs with no declared tier
anthropic+openai / copilot10139 34.6Up to 57 sub-agents on one turn; single delegates at 134 tool calls and 2.3M tokens

Neither extreme is coordinated. One repo held 12 worktrees and ran everything in the primary while a single Copilot turn convened 57 agents under no tier; the same turn's delegates ran to 4.1M tokens each. GO7 caps fan-out width; CTX-F already records that it does not cap depth. The registry insight generalises: contention — and cost — are properties of the artifact and the delegation, not of the session boundary. A pack that classifies its files and leaves its delegations unclassified has solved the cheaper half.

Concretely: extend the delegation contract with a per-branch tool-call and token budget that the child reports against, exactly as P1 extends the artifact registry — and treat the budget firing as a finding, never as a stopping argument.

04

What I am not proposing

The Simplifier's pass. Each of these was considered and struck, with the reason, because a proposal that only adds is not a proposal.

  • A session-contract document per repo. The template exists (templates/session-contract.template.md) and coord collaborate check already requires one when multiple sessions are active. Nothing is missing; it has simply never been reached, because the layer is off. P2 fixes the cause. Adding a second document would be ceremony added to remove ceremony.
  • A lease on every authored file. The engine's own measured comment is the counter-argument: the six busiest files in the reference repo are all generated, so a uniform lease aims at 13/60 and misses 58/60. Classification is the leverage; leases stay for the genuinely contended minority.
  • Enforcement of worktree-per-session. Struck in favour of P5's counter. There is no measured baseline for how often the WT4 exception is correct, and a refusal built on no baseline is exactly the tuning-from-a-feeling this exercise exists to prevent.
  • A parallelism push. The CFD plan's section 07 is right and it is worth repeating here rather than quietly dropping: parallelism is a cost multiplier, roughly 15× for orchestrator-worker exploration. The anthropic+openai/copilot row above is that multiplier being paid without the decision being made. The fix is a budget, not more agents.
05

One thing about how this was measured

Any coordination framework is going to be judged by a compliance number, so the instrument has to be trustworthy first. This one is not, yet.

session-profile.py:132 matches Goal: with a required colon. CT19 and every worked example in the pack write **Goal** · or **Goal** —. Across 346 substantive Claude-Code turns the detector finds 10 goal states; widened to the prescribed form it finds 15. no_goal is 471 of the 515-turn drift total — the largest single term in the metric used to tune per-family guidance.

The finding survives the correction — 15 of 346 is still a real adherence gap, and SP-09 stands. But the detector degrades as compliance improves, because every newly conformant turn is written in exactly the form it cannot see. Registered as CTX-J; the fix is one regex and the control is a fixture asserting each documented spelling is detected.
