Owner / Coordinator / Sub-Agent coordination across one, several, and federated harnesses

Thesis

Designated leader in a compare-and-swap cell (a git ref), recorded in the ledger, fenced at the join — never elected, never arbitrated by a union merge. Five-part delegation contract whose fifth part is the termination condition, and whose cross-harness form carries a deadline and a fallback. Mechanical Owner review: typed decision requests answered by numbered rulings. And the distinction between a spawned relationship (the parent holds the process: push, liveness and join are free) and a registered one (peers share only files and git: push is best-effort).

S2 is spawned-native. S1 is spawned-remote. S3 is registered. The same objects flow through all three; only the channel differs.

Everything else the prior proposals add — a loopback bus, a cloud relay, phi-accrual stall detection, automatic reassignment, per-sub-agent worktree mandates, an interactive board — is already shipped by a harness, contradicted by a measurement, or has no measured trigger. Each is listed in §06 with the number that would justify building it.

Evidence base: docs/knowledge/multi-agent-coordination/. Record: owner-coordinator-subagent-coordination.md (this page is the reading view).

03

The model

Owner

Most capable model available

Answers decision requests with numbered rulings; holds the veto; sets the mandate; escalates to the human when a ruling's reversibility or blast radius exceeds it. Never grants leases, never authors track work, never answers a permission prompt for the human, never clears its own veto.

Coordinator

Capable enough to decompose and join

Decomposes for disjoint authored sets; authors shared contracts before fan-out; dispatches under five-part contracts; watches progress; joins; holds the leader designation in S3. Never authors track work, never widens fan-out past the cap, never reassigns without a ruling.

Sub-Agent

Fit for the task

Executes one contract in one worktree; returns artifact references and proof of done; may nack a contract outside the mandate. Never re-plans, never touches another track's authored set, never spawns teams, never relays a denied action.

Seats are seats, not processes: in S2 the Owner and Coordinator are usually one process in two modes, and the veto rule is satisfied by a separate review sub-agent on the Owner-tier model. Vocabulary: Owner is the model seat; the person is the human operator; ai-de's AgentPlane conductor keeps its name.

Invariants

  1. Leadership is a CAS cell (refs/coord/leader via update-ref <ref> <new> <old>), recorded in the ledger, fenced at the join.
  2. Designate, don't elect. Reclaim after expiry + quiet period with a strictly higher epoch; a contested claim pages the human.
  3. Path leases are efficiency locks; TTL 300/900 unchanged; git is the correctness arbiter.
  4. Never --force with --force-with-lease; always the three-part form.
  5. Liveness from the world; heartbeats carry progress; "no end recorded" is never rendered "live".
  6. Five-part contract; artifacts not prose.
  7. Every cross-harness request carries a deadline and a fallback; ACK pinned to a blob hash.
  8. Two tracks never author one file or one slice in the same window.
  9. An agent message is never consent.
  10. Never advertise a channel not executed on this machine.
  11. Empty fleet view is NOT CHECKED.
  12. Fan-out declares all GO7 fields and a main-line budget; width 3–5 by default.

S3 — several harnesses, each self-contained, one designated leader

  1. Register: coord session start --host <h> --roles coordinator → Session Card.
  2. Designate: the human runs coord leader pin <session> --ttl 300 → CAS on refs/coord/leader, epoch +1, ledger line.
  3. Own: each harness's authored set is in the one ownership register; artifact classes decide what needs no coordination at all.
  4. Coordinate seams: request add --deadline --fallback; consumer ack --blob; producer resolve. At the deadline with no ack the requester runs the fallback and records expired-fallback — "not waiting on Codex" as a protocol step.
  5. Lead: the leader holds the running track, re-folds every 15 s, notifies waiters on done/release, kicks on deadline or three missed beats, escalates. It advises assignment; coord claim still grants.
  6. Renew / lose / reclaim: renew at TTL/3; a lapsed designation is reclaimable after a 30 s quiet period with epoch +1; the takeover re-establishes the in-flight table before acting.
  7. Push by the cheapest verified channel: Claude↔Claude native message; stop-class hook inbox drain; otherwise inbox file + SessionStart count. Recorded per host as enforced / observed-only / unsupported.

Today, without §07: everything except leader, typed request states and track exists. The human names the leader in the session contract; the leader runs coord tail and coord collaborate summary on a 15 s monitor; Claude Code peers use SendMessage. That is S3 as ai-de runs it now, with ai-de's failure rates.

08

Defect class registered from this turn

CTX-Q — A parent enters a worktree after delegating, stranding its delegates. Four research sub-agents were spawned from the primary checkout; the parent then entered a worktree; the worktree guard resolved each sub-agent's cwd to the shared checkout and refused every shell call for the rest of their runs. Control: the always-loaded doctrine (P0) carries "enter the worktree before the first spawn", and the coordination skill refuses to spawn while the worktree state is pending. Registered as uncontrolled until P0 lands.
