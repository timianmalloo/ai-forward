Proposal · directive review · analysis only

Where else should a directive be structure, not prose?

CT19 just proved the pattern: the pack held the right rule as a sentence, and extended-reasoning models skipped it on ~78% of substantive turns. Promoting the goal-state opening to a fixed, audit-mapped block closed the gap. This is a disciplined sweep of the rest of the directive set for the same shape — a recurring obligation, expressed in prose, that an agent routinely skips because prose is not mechanically checkable.

This is a proposal, not a change. Nothing here is implemented. It is analysis for your decision. The recommendation deliberately promotes few things — over-promoting prose to structure is itself the ceremony inflation the pack fights (CT15, the Simplifier). The negative space — what must stay prose — matters as much as the candidates.

The pattern CT19 established

The runaway-session investigation found the drift is an enforcement gap, not a directive gap. The pack already tells the agent to open every non-trivial turn with a goal-state and a stop condition (CT19). Measured against the audit log, that opening was recorded on roughly 1 turn in 5. A directive an agent reads and skips four times out of five is, operationally, not a directive.

Promotion worked because it did three things at once:

  • Named the fields. Prose (“state the goal, the stop condition, and what's out of scope”) became a fixed block: Goal / Done when / Not in scope.
  • Mapped to a checkable surface. The block maps to the audit log's goal and done_when fields — so its presence is observable, not asserted. audit-log.py selfcheck now reads it back.
  • Stayed bounded. The check reports presence gaps; it never issues a scope verdict (a bounded critique, not unbounded reflection).

The three-part test below is derived directly from that: a prose obligation earns promotion only when it is recurring & skip-prone, has nameable required fields, and maps to a surface that can check it. Structure with no checking surface is just tidier prose — not enforcement.

Promotion criteria (all three, or it stays prose)

CriterionThe questionWhy it gates
1 · Recurring & skip-prone Is this a per-turn or per-task obligation that agents demonstrably skip? One-off obligations don't accumulate skip debt; the 78% signal is what justified CT19.
2 · Nameable fields Does the obligation carry specific fields presently buried inside sentences? If it can't be reduced to fields, a structure would flatten judgment into a bad form.
3 · Checkable surface Is there an existing artifact (audit log, marker grep, Proof Pack, frontmatter, a gate) where the structure becomes observable? Structure without a reader is decoration. The audit-map is what made CT19 real.

Tier 1 — recommended now: the two inline markers

Recommendation: promote NG4 and L5 together.

They are the closest analog to CT19 that exists: a recurring, per-instance obligation, with named fields stated only by example, and an existing harvest surface (both markers are already greppable and already fed into a ledger by CI9 / L6). The gap today is that field-completeness is unenforced — a marker can ship missing its confirm route or its trigger, and nothing catches it, which is precisely how a triggerless simplify: “silently becomes permanent.”

NG4 — proposed fixed shape

# assume: <belief>
#   confirms-when: <what would verify it>
#   breaks-if: <what fails if it is false>

Same content NG4 already requires — now with labels a lint can check for.

L5 — proposed fixed shape

# simplify: <the shortcut>
#   ceiling: <the limit it is ok up to>
#   upgrade-when: <the trigger to revisit>

A marker missing upgrade-when is the rot mode L5 already names.

The checking surface already exists. scripts/check-consistency.py (or the existing marker harvest) can assert that every assume: / simplify: marker carries its labelled fields — the exact selfcheck move, applied to markers instead of turns. Small blast radius: the labels are additive, and a free-form marker can be grandfathered with a warning rather than a hard fail (mirroring V16a — a suggestion warns, a defect fails).

Tier 2 — worth doing, larger blast radius: E7/E8 and IO2

Recommendation: adopt as an opt-in Proof-Pack section for the work that triggers them, not a new mandatory per-turn block.

E7/E8 is high-value — it backs two recurring defect classes — but the surface list “differs per architecture” (E7's own words), so a fixed block would be wrong. The right structure is a generated checklist inside the Proof Pack for a T1/T2 field-change: one tick per surface the change reached, one row per new field with its writer and its compute-reader traced. That keeps the discipline checkable without pretending the surface set is universal.

IO2 is a clean question → emitting-source table, but it fires on new-capability work rather than every turn, so its skip rate is lower. Fold it into the same Proof-Pack section as E7/E8 rather than giving it its own ceremony.

Why Tier 2, not Tier 1. Both touch the Proof Pack, which is already a committed T1/T2 artifact — good — but a poorly-shaped mandatory checklist would add per-change friction to every field edit. Pilot it as opt-in on one or two /implement runs, measure whether it catches a real miss, and only then consider making it standard. That is the same “measure the skip, then promote” loop that justified CT19 — applied to the proposal itself.

What must stay prose (the negative space)

Equally important, and the guard against turning this into its own ceremony engine. These fail criterion 2 — they are judgment or recognition, not fielded obligations — and structuring them would flatten the reasoning the pack depends on.

DirectiveWhy it stays prose
NG3 / IO3 / DX3 — the “tells” lists Recognition heuristics, not things the agent emits. A form cannot hold “the sentence started to feel plausible.”
The Rigor Protocol reasoning (map / interrogate / disconfirm) The reasoning is the value; its output — the confidence ledger — is already the structured part.
The simplify:/assume: rationale prose Promote the fields (Tier 1), never the free-text explanation. The “why” is prose by design (CT12).
Already-structured artifacts Proof Pack, confidence ledger, Testing-Strategy trigger table, CT10 close, CI2 — these are the models, not candidates.

Recommended sequencing

  • 1  Tier 1 (NG4 + L5 marker fields + lint). Smallest change, proven pattern, existing harvest surface, additive labels. Highest value-to-risk ratio. One /specify→/implement loop.
  • 2  Tier 2 pilot (E7/E8 + IO2 as an opt-in Proof-Pack section). Run it on one or two real /implement runs, measure whether it catches a miss, promote to standard only if it does.
  • —  Tier 3: no action. Already adequate or correctly prose.

Each promotion should carry its own selfcheck-style reader, and each should stay bounded — reporting presence, never issuing a verdict. The discipline that made CT19 safe is the discipline that keeps this from becoming the very ceremony it is trying to remove.
