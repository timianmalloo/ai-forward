## 2. Recovered system map (Stage 2)

The repository is **two things at once** (dogfooding): the canonical **source** of the AI-Forward Pack
(`pack/`) and a **live install** of it (`.claude/`, `.github/`, `docs/`), generated by
`tools/sync-pack.ps1`. `docs/architecture.md` (refreshed to rev53 in this review) is the recovered
architecture of record; it was **stale** at entry (claimed rev49 / 22 skills / 118 nodes — see FR-072).

- **Source of truth:** `pack/` — 39 knowledge docs, **24 skills** (`commands/*/SKILL.md`), 28 templates,
  18 deployable scripts, adapters (Claude agents, Copilot prompts, INSTALL.md deployment map, managed blocks).
- **Generated surfaces (never hand-edited):** `.claude/`, `.github/{instructions,prompts,agents}/`,
  `docs/ai-forward-pack/`, `docs/docs-index.js`, `docs/audit/audit-data.js`, portal/pack indexes.
- **Tooling:** `tools/` — `sync-pack.ps1` (regenerate), `verify-bundle.ps1` (the 9-gate front-door proof
  mirroring CI), `package-pack.ps1`, plus Python build utilities.
- **Verification:** `tests/docs_explorer/` (360 Python + node core tests), `pack/evals/` (33 eval cases),
  `.github/workflows/pack-consistency.yml` (runs `npm ci` then the gates).
- **Knowledge graph:** `docs-graph.py` over V2 frontmatter → `docs-index.js` → Docs Explorer; audit/change
  logs via `audit-log.py`.

Trust boundaries are modest (a local dev/build tool, not a network service): the filesystem, the git
repo, `subprocess` invocations of node/python/git, and — for optional features — Graphify/Obsidian and
generation backends. No production runtime, no persistent datastore, no user PII.

## 3. Assessment by layer (Stage 3)

**Architecture — coherent.** Single-source-of-truth with a mechanical drift gate (gate 2) is the load-bearing
invariant and it holds. Dependency direction is clean (source → generated; tooling → source). The dogfooding
loop is the main structural risk and is controlled by the gate set. LOA N/A (no AI runtime in the pack itself).

**Design — sound.** Scripts are stdlib-only, single-purpose, CLI-shaped with `--dry-run`/`--check` smoke modes.
Idempotent regeneration + comparison (gate 2) is the correct anti-drift design (FR-057 history). Error model is
consistent (`try/except OSError`, narrow suppressions). One design smell: `coord-core` uses `shell=True` on a
config-derived regen command (FR-075).

**Implementation — clean.** No bare `except:`, `eval`, `exec`, or `os.system` in source; no hard-coded secrets;
markers are disciplined (`coord-core` `simplify:` markers all carry ceiling+trigger; the single `TODO` in
`docs-graph.py:1261` is the stub-scaffold placeholder text, **not** rot — disconfirmed). SIM115 resource-lifecycle
class fully remediated this session.

**Testing — strong where it counts, thin at the edges.** 360 tests cover the graph, coordination, audit,
federation, and deployed scripts; mutation-adjacent contract tests exist. Gap: five `tools/` build/scaffold
scripts are untested (FR-074); the build-* outputs are indirectly gated by parity checks, but `new-capability.py`
(the `/extendaibundle` scaffolder) is neither unit-tested nor output-gated.

**Traceability — good.** Skills → prompts parity is gated (gate 1); graph frontmatter links are validated; the
audit/change log ties decisions to commits. Two new skills lack portal editorial metadata (FR-073).
