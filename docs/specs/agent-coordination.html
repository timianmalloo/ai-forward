Specification · draft · tier T2

Agent coordination

Shared context and explicit coordination across worktrees and agents — so several agents can work one repository at once without losing work or time. Grounded in measured evidence from TheTerrace, HealthWatch and Meridian, not in preference.

What changed from the draft, and why

Converges AGENT-COORDINATION-SPEC.md v0.1 and its decision explorer

The draft is a good design for one of the four failure modes actually observed. Its thesis — claims, not commits, are the unit of coordination — is kept and sharpened. Four things are corrected, each by measurement rather than by preference.

The draft saysThe evidence saysConsequence
Path/symbol leases are the central mechanism. The six busiest files in TheTerrace are all generated — 58/60, 58/60, 58/60, 54/60, 35/60, 33/60 of the last 60 commits — against 13/60 for the busiest hand-written source file. Neither agent's authored work disagrees; the generator ran twice. A lease would have prevented none of these, and would have serialized work that is not in contention. Leases are scoped by artifact class. Derived artifacts are regenerated — never leased, never merged.
The log is safe because ids are ULIDs. True for the new log, and it leaves the existing collision untouched. KG-B has nine recorded occurrences, twice reaching main, once silently destroying an entry. A full 22-branch remote scan was built, works, and still collided within the hour. Collision-proof allocation becomes a first-class service of this layer, serving the repo's existing registers — the only rung (make it impossible) the evidence shows holding.
The worst case is a stale lease. The worst case observed is lost work. Two sessions shared one directory; git add -A swept one's files into the other's commit; the swept product work became reachable from exactly one ref. A later sweep of 27 worktrees found five holding 19 commits that existed nowhere else. Work preservation is a goal of equal rank, with its own invariants and its own acceptance criteria.
Invariants are “enforced by agentctl, stated in AGENTS.md”. CLAUDE.md had warned against git add -A in prose, in the file every session reads at grounding — and the delivery script did it anyway, because prose does not fail. A rule that ships only as prose is out of scope. Every invariant carries a named mechanism and a red-first proof obligation.

A fifth correction is about cost, not correctness: the draft assumes a .NET 10 global tool. Three of the four repositories in evidence are .NET, but the layer is federated by a pack whose entire script surface is dependency-free and whose install target may have no .NET SDK. That is an architecture decision, recorded here only as a portability requirement (NFR-P2).

The problem is four problems

Part A · functional — only the first is a merge conflict

58/60commits touching the busiest file — and it is generated
9recorded id collisions across branches, two reaching main
19commits found existing in exactly one place, across 27 worktrees
20%of the last 100 gate runs produced nothing at all
M1 · structural conflict

Two branches regenerate the same committed artifact

Nobody's authored work disagrees; the generator ran twice. With 26 worktrees in play, any two concurrent branches conflict by construction. Its real cost is indirect and compounding: a conflicting PR runs no gate at all — GitHub builds a merge commit to run pull_request workflows, so a conflicting PR runs none of them, and gh pr checks answers “no checks reported on this branch”, which is indistinguishable from a trigger that failed to fire. Two pushes were spent re-triggering a gate that was never going to start.

M2 · allocation collision

A shared register mints its next id by reading the local file and adding one

Two branches both take the next free number, because neither can see the other. The conflict then presents as an ordinary content conflict, and the obvious resolution — dedupe by id, keep one — silently destroys one of the two entries. Nine occurrences; one recurred during the work that was preventing it.

M3 · silent divergence

Two agents independently author the same rule, and git merges both cleanly

Nothing fails, because each copy is correct on the day it is written. In Meridian one quantity — “what an account is worth” — had six implementations, one already drifted (!= 0 where every money-deciding path tested > 0), so two surfaces reported different net worths and nothing compared them. The most expensive mode, and the only one git will never report.

M4 · work loss

In a shared tree, one session's checkout moves another's HEAD

An unscoped git add -A commits another session's files under a message describing neither, and work ends up reachable from a single transient ref. One near-miss during the writing of the investigation that found it; then five of 27 worktrees holding 19 commits that existed in exactly one place. Recovery depended on a human noticing, which is not a control.

Underneath all four is one shape the repository's own doctrine already names: procedure that exists as knowledge rather than as mechanism. An ordering rule, a canonical command, a merge strategy, an id scheme — each written down, each read, each violated by someone who had just cited it. CI6: a lesson recorded as prose is a memoir.

So this spec is not “a lease server”. It is: give concurrent agents the smallest set of shared facts that makes each of the four modes impossible to express, and ship each of those facts as something that fails.

Core scenario

If this works end to end, the capability is worth building

Three sessions are open on one repository, each in its own worktree: Opus on a data-ingestion work item, Copilot extracting a client interface, and a GPT harness on a page that consumes both.

Opus announces its intent and claims src/Ingest/**, stating in the announcement what it searched for first and what came back. The claim is granted. It needs a new entry in the defect-class register, and asks the layer for an id; it is issued one that no other session can be issued, ever, without either of them coordinating. It edits, and its harness lets the edits through because it holds the lease.

Copilot claims src/Clients/** — disjoint, granted immediately, no serialization. It then needs to touch the composition root, which is registered as a hotspot: the claim is refused with the reason and the owner, and Copilot instead records a request against the integrator and continues with the rest of its work item.

The GPT harness announces a work item that depends on a type Opus has not written yet. Before it starts, it reads the decisions in force for the artifacts it will touch and finds one Opus recorded twenty minutes ago — this DTO lives in the contracts assembly — so it does not invent a second home for it. It records that it is blocked, and the block is visible to Opus rather than being discovered at merge.

Opus finishes, releases, and pushes. Its branch conflicts on two committed derived artifacts, because Copilot merged first and the generator ran twice. The conflict is resolved by regenerating, not by merging, and the resolution stages the files it wrote by name — so the untracked work sitting in the tree from another task is not swept into the commit. Opus then asks the layer whether it is safe to move HEAD; because everything is pushed, the answer is yes.

At the end of the day the Operator asks one question and gets one answer: which trees are waiting, what has been decided, and whether anything exists in only one place. Nothing does.

Every clause in that scenario corresponds to a defect with an instance and a date.

Scope, and the non-goals with their reasons

An explicit non-goal is as load-bearing as a goal

In scope

  1. A shared, append-only record of intent — claims, decisions, blocks, completion — written before the working tree moves, one writer per file.
  2. Leases over artifacts, scoped by artifact class, enforced at each harness's edit boundary and at the commit boundary universally.
  3. Collision-proof id allocation as a service to the repo's existing registers, not only to this layer's own log.
  4. A decision register with an enforced pre-write read (M3).
  5. Work-preservation invariants: stage by name, never move HEAD over unique work, one session per working tree.
  6. A derived-artifact declaration, so structural conflicts are resolved by regeneration rather than by merge.
  7. A projection: a bounded per-agent context view, and an operator status view.
  8. Federation — installed and updated by the pack, configured per repo.

Out of scope

  • Semantic merge resolution. Regeneration and refusal are in; understanding both sides is a different, much harder capability.
  • Replacing GitHub Issues / Projects. Work items here are in-flight handles; the backlog stays the system of record.
  • A planner that assigns work. Nothing in the corpus attributes overlap to bad assignment, and a planner's dependency model goes stale faster than it is consulted.
  • Multi-machine / cloud agents. Designed for — nothing may assume a shared filesystem or a single clock — not built.
  • A second audit log. The pack's audit log records what was done; this records what is being attempted. Different grain, different lifecycle. They share the allocator and duplicate nothing.
  • Replacing the docs knowledge graph. A coordination “graph” that re-modelled documentation would be a second source for one quantity.
  • A merge queue. GitHub has one; this layer supplies the ordering signal.
  • Enforcing an agent's reasoning. The layer can refuse an edit; it cannot make an agent think. Every mechanism fails closed on a fact, never on a judgement.

Conceptual domain model

Bounded context: agent coordination — work in flight. Adjacent and deliberately not absorbed: Delivery, Knowledge Graph, Audit & Change Log

Grain, declared before any column: one row of the coordination record is exactly one event emitted by one session at one instant.

User stories & acceptance criteria

Every criterion falsifiable; every threshold drawn from a measured baseline

US-1 — Know before I edit whether another session is already changing this artifact

  • Given no unexpired lease overlaps src/Ingest/** When a session claims it Then the claim is granted, within NFR-P1.
  • Given A holds an unexpired hard lease on src/Ingest/** When B claims src/Ingest/Reader.cs Then the claim is refused, naming holder, work item, expiry, and one remedy.
  • Given two patterns whose intersection cannot be decided Then the claim is refused — a false refusal is preferred to a false grant, and the layer says which it did.
  • Given a lease-holding session stops emitting liveness past its TTL Then an overlapping claim is granted, and the expiry appears in the operator view as an event, not as an absence.

US-2 — An edit to an unclaimed artifact is refused, not warned about

  • Given enforcement is enabled When a session writes an authored artifact it holds no lease on Then the write is refused before it happens, in a form the model can act on.
  • Given a harness with no pre-edit hook When it commits an artifact it never claimed Then the commit is refused. The commit boundary is the universal floor: every harness has one.
  • Given the lease state cannot be determined Then enforcement says so and refuses to imply it looked. A control that cannot see is not licensed to accuse, and certainly not to report a pass.

US-3 — An identifier that cannot collide, even if neither session has pushed

  • Given two sessions request an id for the same register within the same second, in separate worktrees, with no network Then the two identifiers differ. This is the exact shape that defeated a working 22-branch remote scan.
  • Given a register whose ids are currently sequential When the layer is adopted Then every existing identifier keeps its value and no reference is rewritten.
  • Given an id was issued When its branch is abandoned Then it is never reissued.
  • Given two branches each appended to the same register When merged Then the result contains both, and a resolution reducing the entry count below the sum of distinct entries fails closed. A “dedupe by id” resolution reported “203 ours + 203 theirs → 203 unique” and destroyed an entry. Arithmetic caught it; nothing else did.

US-4 — Know what has already been decided about what I am about to touch

  • Given decisions are in force on claimed artifacts Then they are returned with the grant — the agent does not have to know to ask.
  • Given a session disagrees Then it must record a superseding decision; the original is retained and marked superseded, never edited.
  • Given an announcement to create a new artifact carries no record of a prior-art search Then it is reported incomplete. An unevidenced search is indistinguishable from no search.

US-5 — Conflicts on generated files stop being conflicts

  • Given an artifact declared derived When two branches both regenerate it and merge Then resolution is by regeneration, byte-identical to a clean generation from the merged source.
  • Given a conflict outside the declared derived set Then the tool fails closed and changes nothing.
  • Given a resolution has run Then it stages only the paths it wrote, by name, and names every file it left alone — silently declining to touch a file is indistinguishable from never noticing it.
  • Given a PR is conflicted Then the status distinguishes “conflicted, therefore no gate will run” from “the gate has not reported yet.” These are the same silence today.

US-6 — Refuse any operation that would leave work reachable from nowhere

  • Given HEAD holds commits reachable from no other ref When a checkout, reset --hard, rebase or branch -D is attempted Then it is refused, the at-risk commits are listed, and push is offered as the remedy.
  • Given a single at-risk commit Then it is counted. The first implementation of this guard reported SAFE for exactly the case it existed to catch; a second bug lost the count when there was only one. A guard that fails open is worse than no guard, because it is trusted.
  • Given a tree already occupied by a live session Then a second session is refused, with the occupant named.
  • Given any tool in this layer stages Then it stages by explicit path. A wildcard stage anywhere in the layer's own surface — or in any agent-facing prompt it ships — is a defect, detectable by scanning the shipped text.

US-7 — One place that answers “which tree is waiting, and is anything held in only one place”

  • Given any number of worktrees Then each is listed with branch, drift, held leases and unique-commit count, and a non-zero count is visually and exit-code distinguishable.
  • Given a prune Then no branch that is checked out anywhere, and no branch carrying unique work, is deleted — the two ways an automated cleanup does damage.
  • Given the last N hours Then claims, refusals, decisions, blocks and completions appear in one chronological view across all agents.

US-8 — Installed and updated by the pack, in every repository

  • Given a pack update Then the layer arrives with it and the repo's own configuration is preserved, not overwritten.
  • Given no artifact-class registry is configured Then the layer runs in advisory mode and says that it is advisory, rather than implying enforcement it cannot deliver.

US-9 — The layer's own record is incorruptible by the operations performed on it

  • Given a record file whose last byte is not a newline When the next event is appended Then the two records do not fuse. The prior instance fused two entries into one unparseable 2,323-character line, exit code 0, and both were lost — the new one and the innocent one before it. The duplicate-id and ordering checks both reported PASS on the file that had just eaten two records.
  • Given any step returns non-zero Then the tool throws by step name. No tool here may print a success line that is a statement about having reached the last line. A failed push printed its usage hint into a discarded stream while the script announced “rebased on origin/main”; four commits stayed local for twenty minutes.
  • Given a tool claims to have changed state Then it has read the state back. An exit code is not a result.

Non-functional requirements

ISO/IEC 25010 — each a threshold, each with the instance that set it

RefRequirementWhy this number
NFR-P1
performance		 A pre-edit check adds < 100 ms p95 at ≥ 5,000 tracked files and a 10,000-event record. Claim / release / allocate < 250 ms p95. A full fold < 2 s. The check sits on every edit. A hook that costs a visible pause is a hook that gets disabled — and a disabled hook is worse than none, because the invariant is still assumed.
NFR-R1
reliability		 Zero record-fusing appends under a named adversarial corpus. Zero success reports from a tool whose step failed. Replaying the record twice yields identical folded state. Both fusing and false-success have instances with dates. Fold idempotence is what makes the record, rather than a database, the source of truth.
NFR-R2
reliability		 The layer fails safe, never open: any state it cannot determine produces a refusal-with-reason or an explicit “not checked”, never a silent pass. A guard that reported SAFE for the case it existed to catch; a control that accused its own branch because CI checks out a detached HEAD.
NFR-S1
security		 Content written by one agent and rendered into another's context is untrusted data: length-bounded, structurally delimited, never carrying instruction authority. The projection is a model-to-model channel. This is a prompt-injection boundary and the one genuinely new trust boundary this layer creates.
NFR-S2
security		 Enforcement is a local integrity control, not a security control: an agent with shell access can bypass it — and the layer says so. Claiming a security property the mechanism does not have is how a control gets trusted past its limit.
NFR-V1
privacy		 Anything git-tracked and pushed passes the pack's existing scrub first; intents are length-capped. Intent text is model-authored and unbounded; the record is pushed.
NFR-C1
compatibility		 Three harness families can perform every verb. No verb reachable only through one vendor's surface. Nothing assumes a shared filesystem or a single clock. “Model/tool agnostic” is a stated goal; the honest test of it is three, not two.
NFR-C2
compatibility		 Adoption changes no existing identifier and requires no rewrite of history. The reason the last prevention was applied to one id scheme and not its sibling.
NFR-P2
portability		 Windows, Linux and macOS, with no runtime the pack does not already require, no network, and no daemon that must be started before an agent can work. Its control suite runs on all three in CI. A control suite silently coupled to one OS; a deployed script broken by a runner's language-version auto-upgrade; a documented interpreter name that is a store alias, not the interpreter.
NFR-M1
maintainability		 Emits the four metrics it exists to move: conflicts per merged PR, % of edits under a held lease, mean/p95 wait on a refused claim, commits reachable from exactly one ref — all derivable from the record plus git. A layer that cannot show it moved the numbers will be kept or removed on taste.
NFR-M2
maintainability		 Every invariant is a named control, observed failing on the un-fixed shape before it is trusted, and enumerable. An invariant that reaches only the “always-loaded instruction” rung must say so. CI6, and the control ladder: make it impossible > automated control > always-loaded instruction > knowledge doc.
NFR-U1
usability		 Per-turn coordination context ≤ 2,000 tokens, always a projection. A refusal is actionable in one read. Context spent on coordination is context not spent on the work.

Part B — UX specification

Medium: command-line and tool surfaces. Two readers — a model, and a human. Part C is N/A: no visual UI in v1.

The Agent

No memory between sessions, cannot see the other worktrees, optimising for finishing. As measured repeatedly: it will comply with a rule it is told, right up until the moment complying is inconvenient — at which point only a mechanism holds.

Success: it never has to ask “is anyone else in here?”, because the answer arrives with the grant.

The Operator

Opens a terminal after hours of unattended fleet work. 27 trees, 135 branches, limited attention, and a real fear — justified once — that something is held in exactly one place.

Success: one command, one screen, and the dangerous thing is the visually loudest thing on it.

Information architecture — four surfaces, each answering exactly one question

  1. The claim path — may I touch this, and what should I know first? The grant carries the decisions in force; the refusal carries holder, reason, remedy.
  2. The stream — what has been happening? One merged chronological view across all sessions.
  3. The status view — which tree is waiting on me, and is anything held in only one place?
  4. The projection — what do I, specifically, need in context? Budget-capped, regenerated rather than accumulated.

One label is deliberately blunt: refused — never “denied”, “blocked” or “unavailable”. The reader is a model that must not be able to read the outcome as a transient failure worth retrying. In every surface the order is: what must I not do → what is waiting on me → what happened. Never chronological-first.

Wireframe-level structure

The refusal — the most-read output in the system

REFUSED  src/Ingest/Reader.cs
  held by   opus · WI-142 · expires in 3m12s
  because   an unexpired lease overlaps your pattern
  remedy    wait, or claim a disjoint subset, or record a block on WI-142

Four labelled lines, fixed order, no prose. What happened · who · why · what to do. The remedy is last because it is what the reader acts on.

UX-8A first-time agent is told in one line that the layer is advisory, and what would make it enforcing.An advisory-mode grant indistinguishable from an enforced one.

Part C — UI specification: N/A. Command-line and tool surfaces only. A browsable HTML lens over the record is an obvious later addition and is deliberately deferred: the measured operator need is answered by a terminal in one command, and an HTML surface would add a build step and a generated committed artifact — a new instance of the exact class (CI-B) this spec exists to remove.
