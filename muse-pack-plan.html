Muse × AI-Forward Pack — what Muse needs, and the plan to give it to it

Outline for review · ai-forward repo (pack r97, 29 skills, 41 knowledge docs) · Status: PLAN ONLY — nothing implemented. Reply “go” to execute, or mark changes on this page.

One-line finding. Muse is already half-wired by accident: it loads AGENTS.md as project rules and discovers the 29 pack skills through the shared .agents/skills/ surface built for Codex/Antigravity. What it lacks is everything that makes that deliberate — a Muse surface/path map, a sync target, persona registration, hook equivalents, a doctor check, a context-budget profile, and a drift gate. Today it works; nothing proves it works, and the next sync-pack.ps1 change could silently break it.

1. Goal & success criteria

Goal: Muse becomes a first-class pack harness — the sixth surface beside Claude Code, Copilot, Codex, Grok Build, and Antigravity — generated from pack/, never hand-edited.

  • All 29 skills invocable in Muse by name and by description-match, with reference/*.md stage files readable at the stage.
  • The constitution reachable with correct load-scoping: the 13 load: always docs honoured, skill/reference/glob docs read on demand — never pasted wholesale into an always-loaded file (defect class CTX-B).
  • 23 personas convenable (Peer author / Adversary review, author never clears own veto), via Muse's real subagent mechanism or a documented inline fallback.
  • Pack scripts (docs/ai-forward-pack/scripts/*.py, 45) runnable from Muse on Windows with the correct interpreter form.
  • Every claim measured in a live Muse session (CO12 discipline: enforced / observed-only / unsupported per capability), and a gate that fails when the Muse surface drifts.

Not in scope: changing any skill's content, the other five harnesses' behaviour, Muse product changes, or committing/pushing anything.

3. Approach

Follow the pack's own harness-onboarding pattern exactly — it has onboarded five harnesses and the moves are proven: (1) spike the host's real contracts before writing anything (Spike Protocol; INSTALL's “support ≠ identical events” rule), (2) add a surface path-map, never a knowledge copy, (3) generate the surface from pack/ in sync-pack.ps1 + pack-apply.py, (4) add a doctor check that checks files and says so, (5) qualify live and label each capability enforced/observed-only/unsupported (CO12), (6) gate drift. Source in pack/adapters/muse/; edit pack/, sync, commit all surfaces together.

Key decisions to confirm at go: (a) own .muse/skills vs blessed shared .agents/skills — recommendation: bless shared, pin it, gate it (zero new copies; shadowing already resolves there); (b) personas as registered Muse agent definitions if the spike allows, else prompt-injected — recommendation: spike decides, fallback pre-written; (c) hooks — recommendation: no guessed wiring (AGY PK-07 precedent: unwired beats guessed).

4. Steps (phases; each ends with its proof)

P0 — Spike Muse's contracts (no pack edits)

  • Probe: skill discovery roots & precedence, agent-definition format, lifecycle/hook support, MCP config, session-id env, context-prefix size. One probe per question, live in this repo.
  • Proof: spike note with each answer labelled Verified/Inferred + the failing probe where unsupported. Kills or confirms P3/P4 shapes before they're built.

P1 — Muse surface (the path map)

  • Author pack/adapters/muse/muse-surface.md (sibling of codex.md): skills, knowledge resolution, persona modes, scripts/interpreter, coordination identity, hook status table.
  • One Muse paragraph in the AGENTS.md managed block (via pack/adapters/managed-blocks/AGENTS.block.md) pointing at it — path map only, no knowledge paste (CTX-B).
  • Proof: fresh Muse session grounds from the surface doc alone and names resolved paths for 3 cited docs.

P2 — Generate, diagnose, gate

  • sync-pack.ps1: emit/verify the Muse surface (per P0 decision); pack-apply.py parity for consuming repos; INSTALL.md deployment map + revision/changelog entry.
  • pack-doctor.py: “Muse repository readiness” (skills inventory, surface doc, constitution, scripts — filesystem only, catalog not queried; Codex-check wording as template).
  • tools/check-consistency.py + a surface test (tests/, modelled on the Antigravity/Codex surface tests) so verify-bundle.ps1 fails on Muse drift.
  • Proof: pwsh tools/verify-bundle.ps1 green incl. new gate; doctor passes here and fails in a deliberately broken scratch copy.

P3 — Hooks & coordination identity (only what P0 proved)

  • For each of the 6 hook controls: wire Muse-native if supported (--host muse arm), else document the in-skill manual step. Session id → AGENT_SESSION-equivalent mapping for audit/mail/heartbeat ledgers.
  • Proof: live rows — audit start marker consumed with measured duration, doorbell count shown, stop-gate refusal if wired; each labelled enforced/observed-only/unsupported in the hooks README table.

P4 — Persona council

  • Generate Muse agent definitions from pack/adapters/claude-code/agents/ + Copilot adversaries (23) if P0 allows; else ship the prompt-injection + inline-enactment protocol in the surface doc. Respect persona self-sufficiency (no orientation re-reads, CTX-G) and per-spawn budgets.
  • Proof: one real skill run (e.g. specify Stage 4) convenes ≥2 adversaries, author doesn't clear own veto, verdicts recorded.

P5 — Live qualification & budget

  • Run 3 representative skills end-to-end in Muse (specify, investigate, implement dry slice); measure Muse's assembled prefix; add Muse profile to context-budget.py gate.
  • Update INSTALL counts/readiness wording; close with audit-log + change-log entries (the pack's own last-action rule).
  • Proof: qualification table (skill × capability × status) + budget gate green; anything unproven stays observed-only in print.

5. Validation plan (whole plan)

  • pwsh tools/verify-bundle.ps1 — all gates incl. new Muse drift gate (gate 2's sync-then-git diff --exit-code oracle covers the new target).
  • python docs/ai-forward-pack/scripts/pack-doctor.py — Muse check PASS here, FAIL in broken copy (doctor must be able to fail).
  • Live-session proofs per phase above — files existing is never the claim; a Muse session doing it is.
  • Highest-risk check: P0's hook/persona spikes — if both come back unsupported, P3/P4 shrink to documented manual protocol and the plan still succeeds, with smaller scope stated plainly.

6. Risks & open questions

Risks. (1) Blessing shared .agents/skills couples Muse to Codex/Agy edits — mitigated by the drift gate. (2) Muse skill/agent formats may drift with Muse versions — doctor check must version-stamp what it qualified. (3) Always-on growth: the AGENTS.md Muse paragraph spends prefix — budget gate must ratchet it visibly, not absorb it silently (PACK-R).
  • Open: none blocking P0. The three go-time decisions in §3 have recommendations; P0 evidence may overturn (a)/(b) — that's its job.
  • Flagged, out of scope: live-looking keys in .mcp.json — owner to rotate; plan only stops citing that file as a template.
