# Choose a workflow from the problem

You do not need to memorize the skill names. Start with what you are trying to
establish or change, then open the reference for the workflow that fits.

The navigation's **Skill reference** links cover every current pack skill. Each
reference explains when to use it, required input, an invocation, expected output,
human review and recovery. Search can find a workflow from problem words as well
as its command name.

## Set up or understand a repository

Use [addpacktorepo](#skill-addpacktorepo) to install the pack into another local
repository, [updatepack](#skill-updatepack) to reconcile an existing install, and
[adopt](#skill-adopt) to bring an established project into the knowledge workflow.
Use [forensicreview](#skill-forensicreview) when you need a deep assessment rather
than onboarding alone.

## Shape a change before building it

[Collectknowledge](#skill-collectknowledge) establishes unfamiliar domain context.
[Adddomainexperts](#skill-adddomainexperts) adds relevant specialist perspectives.
[Specify](#skill-specify) makes the intended behavior and user experience reviewable.
[Define-architecture](#skill-define-architecture) addresses system-level choices;
[design-slice](#skill-design-slice) makes one component concrete.

[Compile](#skill-compile) makes a request into a structured starting prompt.
[Optimize-graph](#skill-optimize-graph) shapes the execution when real dependencies
or parallel work warrant it. [Also](#skill-also) captures a later addition without
derailing the work already in progress.

## Build, repair or improve software

[Implement](#skill-implement) builds a defined change with checks.
[Investigate](#skill-investigate) establishes a defect's cause and stops for review
of a repair proposal. [Migrate](#skill-migrate) protects current behavior while
making a broad change. [Code-hygiene](#skill-code-hygiene) measures and, on an approved
fix path, removes coding-quality problems.

## Design a user-facing experience

[Ui-design](#skill-ui-design) addresses the interface and interaction.
[Visualize](#skill-visualize) addresses visual assets, not generated substitutes
for working controls. See [the experience guide](#interfaces) for their relationship.

## Share work across agents

[Prepare-for-coordination](#skill-prepare-for-coordination) develops the division
of work. [Execute-with-coordination](#skill-execute-with-coordination) runs that plan
as coordinator. Compilation is part of the per-track native launch handoff, not a
replacement for the plan. Read [the coordination guide](#coordination) before
choosing a launch mechanism.

## Keep knowledge and learn from work

[Document](#skill-document) refreshes the documentation bundle and graph.
[Auditlog](#skill-auditlog) finds prior activity and decisions.
[Prompts](#skill-prompts) and [searchprompts](#skill-searchprompts) help recover useful
requests for inspection and reuse.

[Session-profiler](#skill-session-profiler) measures available session behavior.
[Dream](#skill-dream) proposes consolidated learning for review.
[Apply-learnings](#skill-apply-learnings) reconciles approved learning into reviewable
plans for other repositories. [Extendaibundle](#skill-extendaibundle) extends the
pack itself when a reusable capability is justified.

## Choose less when less is enough

Not every request needs research, a new design, a panel of reviewers and several
workers. Choose the workflow that resolves the next important uncertainty. Keep
the checks required by the risk, and leave unrelated work out.
